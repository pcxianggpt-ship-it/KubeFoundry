# KubeFoundry v0.3.0 部署手册

## 发布包

发布包按目标服务器 CPU 架构分别生成：

```text
kubefoundry-web-v0.3.0-x86_64.tar.gz
kubefoundry-web-v0.3.0-aarch64.tar.gz
```

每个包包含 Java 17 精简运行时、后端 JAR、前端静态文件、远端步骤和验证脚本，以及 `tools/helm-amd`、`tools/helm-arm`。包内 `SHA256SUMS` 覆盖这些文件；部署前会校验清单、运行时架构和符号链接安全性。

Kubernetes RPM、容器运行时、镜像、组件 Chart 和 YAML 不在发布包内，必须由运维人员在目标管理端独立维护于 `kube-media/`。

## 构建

构建机需要 Bash、tar、sha256sum、JDK 17（含 `jlink`）、Maven 3.8+、Node.js 18+ 和 npm。

```bash
KF_TARGET_ARCH=x86_64 KF_JAVA_HOME=/opt/jdk-17 bash package.sh
KF_TARGET_ARCH=aarch64 KF_JAVA_HOME=/opt/jdk-17-aarch64 bash package.sh
```

交叉构建 ARM64 时，设置 `KF_TARGET_JDK_HOME` 为真实 ARM64 JDK 17。构建脚本会运行后端和前端测试，并生成目标架构的运行时；不得将测试模式生成的包用于生产。

## 部署与升级

在目标服务器上选择与 `uname -m` 一致的包：

```bash
mkdir -p /opt/kubefoundry
cd /opt/kubefoundry
mkdir -p kube-media
# 先将离线介质、Chart 和 YAML 放入 kube-media/
tar -xzf kubefoundry-web-v0.3.0-x86_64.tar.gz
cp kubefoundry-web-v0.3.0-x86_64/deploy.sh .
sudo bash deploy.sh kubefoundry-web-v0.3.0-x86_64.tar.gz
```

默认服务端口为 `10001`，可通过 `--port` 修改。升级前先备份 `data/`；部署会替换 `app/`、`scripts/` 与 `tools/`，保留 `data/`、`logs/` 和 `kube-media/`。H2 数据库迁移仅保证向前兼容，回退前应在备份副本中验证。

## 验证

```bash
curl -fsS http://127.0.0.1:10001/api/health
sudo bash deploy.sh --status
```

响应中的版本应为 `0.3.0`。生产发布前须分别在 x86_64 和 ARM64 环境验证应用启动、Helm 分发及非破坏性组件预检查。
