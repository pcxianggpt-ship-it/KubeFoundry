## 2. 适用范围

本文只描述 v0.3.1 新增或变化的接口。未列出的集群、安装、重置和健康接口继续沿用 v0.3.0 契约。

默认 API 根地址：

```text
http://<管理端地址>:10001/api
```

本文是目标契约，不代表所有字段已经实现。开发过程中如需修改公共字段、状态或错误码，必须先更新技术决策、本文和契约测试。

## 3. 通用约定

### 3.1 内容类型

- JSON 请求使用 `Content-Type: application/json`。
- JSON 响应使用 `application/json`。
- 任务事件使用 `text/event-stream`。

### 3.2 集合响应

```json
{
  "items": []
}
```

### 3.3 异步任务响应

接受任务时返回 `202 Accepted`：

```json
{
  "job_id": 123,
  "status": "pending"
}
```

### 3.4 错误响应

目标格式：

```json
{
  "code": "NODE_IP_DUPLICATE",
  "message": "IP 地址已被当前集群的其他节点使用",
  "details": {
    "field": "ip",
    "conflict_node_id": 8,
    "conflict_hostname": "worker-02"
  }
}
```

规则：

- `code` 是前端判断分支的稳定标识。
- `message` 使用中文且不包含堆栈、SQL、路径外的敏感信息或凭据。
- `details` 仅返回安全的定位信息；未知字段可为空对象。
- 前端不得依赖 `message` 文案判断错误类型。

### 3.5 时间

时间使用 ISO-8601 本地日期时间字符串，示例：

```text
2026-08-09T20:15:38
```

历史任务缺少开始或结束时间时对应字段为 `null`。

## 4. 节点列表与保存

### 4.1 查询节点

```http
GET /clusters/{clusterId}/nodes
```

响应示例：

```json
{
  "items": [
    {
      "id": 5,
      "cluster_id": 1,
      "hostname": "worker-01",
      "ip": "192.168.0.21",
      "ipv6": "",
      "roles": ["worker"],
      "ssh_user": "root",
      "ssh_port": 22,
      "has_password": true,
      "is_draft": false,
      "node_test_status": "success",
      "node_test_message": "测试成功"
    }
  ]
}
```

响应永远不返回 SSH 密码、密文、私钥或主机密钥材料。

### 4.2 新增节点

```http
POST /clusters/{clusterId}/nodes
```

请求示例：

```json
{
  "hostname": "worker-01",
  "ip": "192.168.0.21",
  "ipv6": "",
  "roles": ["worker"],
  "ssh_user": "root",
  "ssh_port": 22,
  "password": "<仅请求时提供>"
}
```

成功返回 `201 Created` 和节点对象。

唯一性规则：

- 主机名和 IPv4 在同一集群内分别唯一。
- 主机名按去空格、去末尾点、大小写不敏感比较。
- IPv4 按标准化后的无前导零形式比较和保存。
- 不同集群允许相同主机名或 IP。

### 4.3 更新节点

```http
PUT /nodes/{nodeId}
```

请求允许提供完整节点或现有更新接口支持的可选字段。唯一性检查排除当前节点 ID。修改关键身份字段后，节点测试状态按现有规则失效。

### 4.4 节点重复错误

| HTTP | 错误码 | 含义 |
| --- | --- | --- |
| 409 | `NODE_HOSTNAME_DUPLICATE` | 同集群主机名冲突 |
| 409 | `NODE_IP_DUPLICATE` | 同集群 IPv4 冲突 |
| 409 | `NODE_IDENTITY_DUPLICATE` | 主机名和 IP 同时冲突且涉及不同节点 |
| 400 | `NODE_HOSTNAME_INVALID` | 主机名格式无效 |
| 400 | `NODE_IP_INVALID` | IPv4 格式无效 |

`details` 可以包含 `field`、`conflict_node_id`、`conflict_hostname`，不得包含冲突节点凭据。

## 5. 测试全部节点

### 5.1 发起全部节点测试

```http
POST /clusters/{clusterId}/node-test?failed_only=false
```

返回 `202 Accepted`。任务类型为 `node_test`，任务内包含当前集群全部可测试的正式节点。

### 5.2 仅重试失败节点

```http
POST /clusters/{clusterId}/node-test?failed_only=true
```

只选择当前 `node_test_status=failed` 的节点。没有失败节点时返回明确的 400 业务错误，不创建空任务。

### 5.3 单节点测试

```http
POST /nodes/{nodeId}/node-test
```

沿用 v0.3.0 行为。同一集群已有活动节点测试任务时，批量和单节点入口都必须拒绝重复提交。

### 5.4 节点测试错误

| HTTP | 错误码 | 含义 |
| --- | --- | --- |
| 409 | `NODE_TEST_ALREADY_RUNNING` | 当前集群已有节点测试任务 |
| 400 | `NODE_TEST_NO_NODES` | 没有可测试节点 |
| 400 | `NODE_TEST_DRAFT_EXISTS` | 存在未完成草稿节点 |
| 409 | `NODE_CONFIGURATION_CHANGED` | 测试期间节点配置已变化 |

## 6. Kubemate 组件配置

### 6.1 查询配置

```http
GET /clusters/{clusterId}/components
```

v0.3.1 响应不再包含顶层 `enabled`：

```json
{
  "configurationVersion": 12,
  "precheckStatus": "success",
  "groups": [
    {
      "key": "nfs",
      "name": "NFS 存储",
      "enabled": true,
      "available": true,
      "components": ["nfs_exports", "nfs_provisioner", "worker_mount"],
      "status": "not_installed",
      "config": {
        "server_address": "192.168.0.24",
        "share_path": "/data/nfs",
        "worker_mount_path": "/data/k8s/nfs",
        "storage_class": "nfs-storage",
        "exports_mode": "managed"
      }
    }
  ]
}
```

JSON 字段命名在实现前由契约测试最终冻结。当前 Java 基线使用驼峰配置版本字段，前端 API 适配层不得同时支持多个不明确名称。

### 6.2 保存配置

```http
PUT /clusters/{clusterId}/components
```

请求示例：

```json
{
  "groups": [
    {
      "key": "nfs",
      "enabled": true,
      "config": {
        "server_address": "192.168.0.24",
        "share_path": "/data/nfs",
        "worker_mount_path": "/data/k8s/nfs",
        "storage_class": "nfs-storage",
        "exports_mode": "managed"
      }
    }
  ]
}
```

规则：

- 组件组选项直接决定是否进入计划，不存在业务总开关。
- 请求按完整替换语义处理；未提交组的处理方式必须由契约测试冻结，不能由客户端猜测。
- 未安装和失败组可修改；安装中和已安装组保持只读。
- 全部组关闭时组件计划为空。
- 旧客户端提交顶层 `enabled` 时，后端兼容忽略并记录弃用警告，不改变任何组值。

### 6.3 MinIO 配置

MinIO 属于 `storage_observability` 组。目标字段在 DEC-001 批准后冻结：

```json
{
  "minio_namespace": "kubemate-system",
  "minio_tenant_name": "kubemate-minio",
  "minio_storage_class": "openebs-hostpath",
  "minio_servers": 4,
  "minio_volumes_per_server": 1,
  "minio_volume_size": "100Gi",
  "minio_request_auto_cert": false
}
```

在 DEC-001 未批准前，这些字段仅是提议契约，不得实现为无版本约束的任意 JSON。

## 7. 任务列表与详情

### 7.1 查询集群安装任务

```http
GET /jobs?cluster_id={clusterId}&job_type=install,component_install
```

目标响应：

```json
{
  "items": [
    {
      "id": 123,
      "cluster_id": 1,
      "job_type": "component_install",
      "status": "partial_success",
      "log_path": "<服务端安全路径或空值>",
      "created_at": "2026-08-09T19:00:00",
      "started_at": "2026-08-09T19:00:01",
      "finished_at": "2026-08-09T19:08:32"
    }
  ]
}
```

规则：

- `cluster_id` 必填于安装概览调用。
- `job_type` 支持逗号分隔的受控类型集合。
- 按任务 ID 倒序返回。
- 是否增加分页必须在数据量测试后冻结；若增加分页，不得改变单任务详情契约。

### 7.2 查询单个任务

```http
GET /jobs/{jobId}
```

返回上述任务对象。集群详情页加载后必须验证 `cluster_id` 与路由集群一致。

### 7.3 查询任务步骤

```http
GET /jobs/{jobId}/steps
```

目标步骤字段：

```json
{
  "items": [
    {
      "id": 301,
      "name": "安装 MinIO",
      "order": 9,
      "status": "skipped",
      "status_reason": "COMPONENT_GROUP_PREVIOUS_STEP_FAILED",
      "component_group_key": "storage_observability",
      "nodes": []
    }
  ]
}
```

### 7.4 查询日志与事件

```http
GET /jobs/{jobId}/logs
GET /jobs/{jobId}/events
```

日志和 SSE 必须绑定请求中的 `jobId`。切换任务时前端关闭旧连接；后端事件包含安全的任务、步骤、组件组和节点标识，不包含凭据。

## 8. 状态集合

### 8.1 任务状态

| 状态 | 是否终态 | 含义 |
| --- | --- | --- |
| `pending` | 否 | 等待执行 |
| `running` | 否 | 执行中 |
| `success` | 是 | 所有要求步骤成功 |
| `partial_success` | 是 | 至少一个组件组成功，至少一个组失败或依赖跳过 |
| `failed` | 是 | 基础/公共前置失败或所有选择组失败 |
| `interrupted` | 是 | 服务中断或任务被中止，结果未完整完成 |

`partial_success` 的最终批准受 DEC-002 约束。

### 8.2 步骤状态

| 状态 | 是否终态 | 含义 |
| --- | --- | --- |
| `pending` | 否 | 未开始 |
| `running` | 否 | 执行中 |
| `success` | 是 | 步骤成功 |
| `failed` | 是 | 步骤执行失败 |
| `skipped` | 是 | 因前置失败或计划规则未执行 |
| `interrupted` | 是 | 执行中断，结果未知或未完成 |

### 8.3 组件组状态

继续使用：

```text
not_installed / installing / installed / failed
```

组件组状态由拥有该状态的任务更新，旧任务回调不得覆盖新任务。

## 9. 新增错误码

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 409 | `NODE_HOSTNAME_DUPLICATE` | 主机名冲突 |
| 409 | `NODE_IP_DUPLICATE` | IPv4 冲突 |
| 409 | `NODE_TEST_ALREADY_RUNNING` | 重复节点测试 |
| 409 | `COMPONENT_COMMON_PREREQUISITE_FAILED` | 组件公共前置失败 |
| 409 | `COMPONENT_GROUP_PREVIOUS_STEP_FAILED` | 组内前序失败，当前步骤跳过 |
| 409 | `NFS_MOUNT_CONFLICT` | NFS 目标存在冲突挂载 |
| 504 | `NFS_MOUNT_TIMEOUT` | NFS 挂载超时 |
| 409 | `MINIO_OPERATOR_NOT_READY` | Operator 未就绪 |
| 409 | `MINIO_TENANT_NOT_READY` | Tenant 或相关资源未就绪 |
| 404 | `JOB_CLUSTER_MISMATCH` | 任务不属于指定集群 |

脚本退出错误如何映射 HTTP 错误只适用于任务启动前或同步预检查。异步任务执行错误应记录为步骤原因码，通过任务详情查询，不把已接受任务改成同步 HTTP 失败。

## 10. 前端路由契约

规范任务详情路由：

```text
/cluster-install/:clusterId/jobs/:jobId
```

兼容路由：

```text
/jobs/:jobId/execution
```

兼容路由加载任务后重定向到规范路由。Spring SPA 转发必须覆盖规范路由，直接访问和 F5 刷新返回 `index.html`，不能返回 Whitelabel 404。

## 11. 兼容策略

- v0.3.1 前端、后端和脚本必须作为同一发布包升级。
- `clusters.kubemate_enabled` 暂保留为兼容列，不参与组件计划判断。
- 旧组件配置请求的顶层 `enabled` 被忽略并记录弃用警告。
- 历史任务的 `started_at/finished_at` 允许为 `null`。
- 旧任务状态不被迁移为 `partial_success`。
- 旧任务详情路由至少保留一个版本。

## 12. 安全要求

- 节点响应不返回密码、密文、私钥或集群密钥。
- MinIO Secret 值不进入 API、日志、事件、快照或错误详情。
- `log_path` 如返回，只允许是受控相对标识或经过安全处理的服务端路径，不得允许客户端读取任意文件。
- 错误响应不返回 SQL、Java 堆栈或远端命令中的敏感参数。
- SSE 和日志只允许读取对应任务的数据；任务与集群归属必须校验。

## 13. 契约测试门禁

- [ ] Java API 测试覆盖全部新增字段、状态和错误码。
- [ ] 前端客户端契约测试与 Java JSON 字段逐项一致。
- [ ] 旧顶层 `enabled` 兼容行为有测试。
- [ ] 节点并发冲突返回稳定 409 错误。
- [ ] `partial_success/skipped` 被前端识别为终态。
- [ ] 新旧任务详情路由刷新测试通过。
- [ ] 无任一响应包含凭据或内部堆栈。

本文中的提议字段在对应决策未批准前保持“目标契约”状态；实现完成后应删除不再适用的提议说明，使本文只描述实际发布行为。
