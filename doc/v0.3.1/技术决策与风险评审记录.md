## 2. 使用规则

本文记录会影响数据库、公共 API、安装状态机、远程系统配置和敏感信息的关键决策。每项决策只允许以下状态：

- `提议中`：方案已提出，尚不可据此实施高风险修改。
- `已批准`：评审结论和约束完整，可以进入对应任务开发。
- `已拒绝`：方案不得实施，必须提交替代方案。
- `已取代`：由新的决策编号替代，历史记录保留。
- `已延期`：移出当前版本，并记录影响和目标版本。

修改已批准决策时不得直接覆盖原结论，应新增决策编号并引用被取代项。评审人、日期和依据为空时，状态不得标记为“已批准”。

## 4. DEC-001：MinIO 固定版本与继续交付

### 状态

`提议中`

### 背景

v0.3.1 要求 MinIO 不再通过 Console 人工创建 Tenant，而由离线 Operator 清单和 Tenant CR 自动部署。MinIO 官方开源 Operator 仓库已经归档，继续交付固定版本会带来许可证、安全修复和 Kubernetes 兼容性风险。

### 提议方案

- 使用发布包内固定版本的 Operator、CRD、RBAC、Tenant 模板和 MinIO 镜像。
- 所有资源记录版本、来源和 SHA-256，不使用在线 Kustomize、Helm 仓库或漂移标签。
- MinIO 作为 v0.3.1 最后一个任务，其他功能联合回归完成后再实施。
- 真实环境只在隔离测试集群执行，失败和重试不得自动删除 PVC、PV、Secret 或数据目录。
- 最终交付 `MinIO真实环境部署与验证操作手册.md` 和独立验收证据。

### 备选方案

1. 从 v0.3.1 移除 MinIO 自动化，保留现有人工流程。
2. 不使用 Operator，改用受支持的独立 Helm Chart 或 StatefulSet 方案。
3. 迁移到有持续维护承诺的对象存储实现，另立版本设计。

### 批准前必须提供

- [ ] Operator、CRD、Tenant API 和镜像准确版本。
- [ ] 发布介质 SHA-256 清单。
- [ ] 许可证和再分发结论。
- [ ] 已知漏洞扫描结果和处置意见。
- [ ] 支持的 Kubernetes 版本范围。
- [ ] 最小服务器、磁盘、StorageClass、PVC 和容量模型。
- [ ] 上游归档后的维护责任人与退出条件。

## 5. DEC-002：组件部分成功状态契约

### 状态

`提议中`

### 背景

当前 `JobService` 在任一步骤失败时终止整个任务。v0.3.1 要求一个 Kubemate 组件组失败后，其他无依赖组件组继续执行。现有 `success/failed/interrupted` 无法准确表达“部分组件组成功”。

### 提议方案

- 任务新增终态 `partial_success`。
- 步骤新增终态 `skipped`，并保存稳定的 `status_reason`。
- 基础安装和组件公共前置使用 `ABORT_JOB`。
- 组件组步骤使用 `ABORT_GROUP`；组内失败后跳过本组剩余步骤并继续下一组。
- 五个可用组件组之间不建立依赖，仍按固定顺序串行。
- 任务状态与组件状态分离：成功组为 `installed`，失败组为 `failed`，未开始组保持 `not_installed`。

### 需要确认的问题

- [ ] 基础 Kubernetes 成功、组件部分失败时，集群总体展示为 `installed`、`installed_with_errors` 还是保持现有状态。
- [ ] `partial_success` 是否对所有任务类型开放，还是只用于 `install/component_install`。
- [ ] 旧前端、SSE 和 API 客户端遇到新状态时的兼容行为。
- [ ] 任务进度是否把 `skipped` 计为“已完成但未成功”。
- [ ] 全部组件组失败时最终状态必须为 `failed`。

### 不变量

- 客户端不得提交失败策略或任意依赖图。
- 已安装组不能因其他组失败回退。
- 中断恢复不得把未知结果标记为成功。
- 同一集群仍只允许一个活动安装类任务。

## 6. DEC-003：节点唯一性迁移策略

### 状态

`提议中`

### 背景

v0.3.0 为支持复制草稿节点移除了旧主机名唯一约束。v0.3.1 需要同一集群正式节点的主机名和 IPv4 均唯一，同时保留草稿复制流程并处理并发写入。

### 提议方案

- V13 新增可空的 `hostname_normalized`、`ip_normalized`。
- 正式节点写入规范化值并建立 `(cluster_id, normalized_value)` 唯一约束。
- 草稿节点两个规范化字段保持 `NULL`，完成编辑时再进入唯一校验。
- 主机名按 `trim -> 去末尾点 -> lower-case` 规范化。
- IPv4 使用严格四段十进制解析并保存无前导零形式。
- 前端做即时提示，后端事务校验，数据库约束处理并发竞态。
- 迁移发现正式节点重复时中止，不自动删除、合并或改名。

### 批准前必须验证

- [ ] 当前测试数据库和待升级数据库的重复扫描结果。
- [ ] H2 在目标版本下对组合唯一约束和多个 `NULL` 的行为。
- [ ] V1、V9、V12 到 V13 的迁移测试。
- [ ] 两个并发请求写入相同主机名/IP 时仅一个成功。
- [ ] 草稿复制、编辑完成、删除和跨集群同值行为。

### 数据处置原则

- 不自动删除节点。
- 不自动选择“保留第一条”。
- 不修改节点 SSH 凭据或角色。
- 冲突清单只包含集群 ID、节点 ID、主机名和 IP，不包含密码或密文。

## 7. RISK-001：NFS 系统挂载修改

### 风险

错误识别挂载点、覆盖非受管 `/etc/fstab`、重复 mount、无响应 NFS 或错误 umount 可能造成节点阻塞、服务中断或数据风险。

### 强制控制

- 使用 `findmnt --mountpoint` 精确查询目标。
- 同时比较挂载源和 `nfs/nfs4` 类型。
- 冲突时只报错，不自动 mount、umount 或覆盖。
- 只修改带 KubeFoundry 标记的受管块。
- mount 设置明确超时并进行后置验证。
- 测试使用临时 fstab 和伪命令；真实测试只在专用节点执行。

### 复核清单

- [ ] 空路径、根目录、相对路径、符号链接和命令注入被拒绝。
- [ ] 已正确挂载时 mount 调用次数为 0。
- [ ] 冲突挂载时 mount/umount 调用次数均为 0。
- [ ] 超时后子进程退出且任务状态收敛。
- [ ] 非受管 fstab 内容前后校验和一致。

## 8. RISK-002：安装状态机与中断恢复

### 风险

组失败后继续执行会增加状态组合；事务失败、服务重启、队列拒绝或迟到回调可能造成任务、步骤和组件状态不一致。

### 强制控制

- 计划和失败策略由服务端生成并进入不可变快照。
- 状态更新校验 owning job ID，旧任务不得覆盖新任务状态。
- 任务接受、步骤创建和组件 `installing` 状态必须具备一致的事务边界和失败补偿。
- 中断恢复不得自动重放远端命令。
- `partial_success`、`failed`、`interrupted` 都必须是终态，SSE 正确关闭。

### 复核清单

- [ ] 提交事务失败无残留活动任务或永久 `installing`。
- [ ] 队列满时任务和组件状态回滚。
- [ ] 服务重启后 running 状态按规则转为 interrupted/failed。
- [ ] A 组失败、B 组成功时两组状态准确。
- [ ] 公共前置失败时所有组件组未被误报为失败或成功。

## 9. RISK-003：MinIO 凭据和持久数据

### 风险

凭据可能通过 shell 回显、命令行参数、日志、事件、测试夹具或验收附件泄露；失败清理可能误删 PVC、PV、Secret 或数据目录。

### 强制控制

- 从系统安全随机源生成凭据，通过标准输入创建 Secret。
- 已有 Secret 时复用，不回显、不写入快照或数据库错误字段。
- 操作手册不得包含真实凭据或要求把 Secret 值粘贴到命令行历史。
- 失败和重试不得自动删除持久化资源。
- 清理操作不属于自动安装失败处理；如需清理必须另行授权和设计。

### 复核清单

- [ ] 日志、事件、API、快照和 Git 敏感信息扫描通过。
- [ ] Shell `set -x`、异常 trap 和调试输出不会泄露 Secret。
- [ ] 重试不会替换现有 Secret、Tenant 身份或 PVC。
- [ ] 真实环境证据已脱敏且存放在 Git 之外。
- [ ] 操作手册明确禁止未经确认删除持久化资源。
