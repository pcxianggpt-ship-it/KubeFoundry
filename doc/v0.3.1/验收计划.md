## 2. 验收目标

验证 v0.3.1 七项优化在配置、数据库、接口、前端、安装编排、远程脚本、任务历史和真实环境中的行为一致。验收必须证明失败边界和数据安全，不以“页面可点击”代替实际集群与任务状态证据。

发布结论只允许：

- `通过`：全部必选项通过，P0/P1 缺陷为 0，所有门禁已批准。
- `有条件通过`：仅非阻断环境项延期，具有责任人、风险和补验日期；MinIO 不允许以未验收状态包含在发布能力声明中。
- `不通过`：任一阻断项失败、关键门禁未批准或缺少有效证据。

## 3. 验收阶段

### 3.1 阶段一：非 MinIO 功能验收

覆盖节点唯一性、全部节点测试、Kubemate 总开关移除、CoreDNS、NFS、组件组失败隔离和任务历史。阶段一通过后才允许开始最终 MinIO 任务。

### 3.2 阶段二：MinIO 最终验收

覆盖固定版本准入、离线资源、Operator/Tenant 自动部署、凭据保护、PVC/Pod/Service/S3、Loki 最小链路、幂等重试和真实环境操作文档复现。

### 3.3 最终发布验收

合并两个阶段结果，完成全量自动化、发布包、升级、文档、安全与真实环境证据复核。

## 4. 验收环境

### 4.1 本地自动化环境

| 项目 | 要求 |
| --- | --- |
| Java | 17，与项目 Maven 配置一致 |
| Maven | 可完成全量测试和 package |
| Node.js/npm | 与 lockfile 和前端构建要求一致 |
| Bash | 可运行仓库测试脚本 |
| H2 | 覆盖 V1/V9/V12 到最新迁移 |
| Git | 支持 LF、暂存范围和差异检查 |

### 4.2 非 MinIO 测试集群

- 使用与生产隔离的专用节点。
- 至少包含一个主控制节点和两个可调度节点，用于 CoreDNS 分布验证。
- 准备一个专用 NFS 测试节点和测试挂载目录。
- 测试前记录节点、磁盘、挂载、`/etc/fstab`、CoreDNS affinity 和工作负载状态。
- 不在生产节点执行挂载冲突、超时或组件失败注入。

### 4.3 MinIO 真实测试环境

- 必须等待最终任务 11 和 DEC-001 批准。
- 拓扑、容量、StorageClass 和 PVC 规划以最终操作手册为准。
- 环境允许保留失败现场和持久卷，不得与生产 Tenant、namespace 或数据目录共用。
- 测试前备份 KubeFoundry 数据库和相关 Kubernetes 资源清单。

## 5. 证据要求

每个动态用例保存：

- Git 提交、版本号、发布包 SHA-256。
- 集群 ID、任务 ID、任务类型、步骤与组件组状态。
- 数据库迁移起点和结果，不保存数据库凭据。
- 必要的 API 响应、SSE 摘要和脱敏日志。
- `kubectl`、`findmnt`、挂载、Pod、PVC、Service 等安全输出。
- 故障注入、修复动作、重试任务 ID 和最终结果。
- 操作人与复核人、执行时间和环境标识。

建议证据目录：

```text
logs/acceptance/v0.3.1/{日期}/{用例编号}/
```

证据目录不得提交 Git。发现密码、Token、Secret、私钥或未脱敏 kubeconfig 时，该用例立即判为安全失败并清理泄露副本。

## 16. 安全与脱敏验收

- [ ] 节点 API 不返回密码、密文或私钥。
- [ ] MinIO 凭据不进入日志、事件、快照、API、异常或测试夹具。
- [ ] NFS 冲突处理不执行自动卸载或覆盖。
- [ ] 数据库迁移不自动删除重复节点。
- [ ] 任务跨集群访问被拒绝。
- [ ] 错误响应不包含 SQL、Java 堆栈或远端敏感命令。
- [ ] 验收附件脱敏并存放在 Git 之外。

任一项失败均为 P0 安全缺陷。

## 18. 缺陷分级

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 数据误删、凭据泄露、节点卡死、迁移不可恢复 | 立即停止，修复并全量重测 |
| P1 | 主流程失败、任务状态错误、组件隔离失效、接口不兼容 | 必须修复，不得发布 |
| P2 | 非主路径错误且有安全绕行 | 延期需书面批准和目标版本 |
| P3 | 不影响功能的显示或文档问题 | 可记录后续修复 |

P0、P1 未关闭数量必须为 0。
