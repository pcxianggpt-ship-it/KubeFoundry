## 任务 3：凭据加密与主密钥管理

- 状态：已完成，待合并。
- 凭据加密：使用 Java 标准库 AES-256-GCM，每条凭据使用独立的 12 字节随机 IV 和 128 位认证标签；密文与 IV 以 Base64 保存，当前格式版本为 1。
- 主密钥：首次使用时在 `${KF_DATA_DIR:data}/secrets/master.key` 创建 256 位 AES 主密钥，后续调用复用；密钥文件使用 Base64，不写入 H2。
- 权限与安全：威胁模型假设当前服务账户是 `secrets` 的唯一写者，同账户恶意进程不在 v0.2.0 防护范围。主密钥仅支持同时提供 POSIX 权限和 `SecureDirectoryStream` 的文件系统；`dataDir` 与 `secrets` 必须为当前服务账户所有、非符号链接且精确 `rwx------`。新建目录原子设置并复核 `0700`，密钥文件在写入前复核为 `rw-------`；无法验证时失败关闭。已有目录或文件权限过宽、所有者不符、符号链接、身份变化或无法提供 `fileKey` 时均拒绝加载；清理仅删除仍与创建时 `fileKey` 相同的空密钥文件。

## 任务 6：主机指纹与集群 SSH 密钥

- 状态：已完成。
- 主机指纹：首次连接按 SHA-256 记录节点主机指纹；相同指纹重复连接直接接受，指纹变化时拒绝连接并保留旧值，错误消息包含节点、旧指纹、新指纹和人工确认建议。
- 集群密钥：每个集群创建并复用一套 Ed25519 密钥，公钥以 `authorized_keys` 格式保存到 H2；引入 MINA 兼容的纯 Java EdDSA 0.3.0 适配依赖，无传递依赖。
- 私钥保护：PKCS#8 私钥先经现有 AES-256-GCM 加密，再写入 `${KF_DATA_DIR:data}/secrets/ssh/` 引用文件；H2 和引用文件均不保存明文私钥，POSIX 文件系统上目录和文件分别使用 `0700`、`0600`。
- 引用校验：私钥引用必须位于本数据目录下，且必须是非符号链接的普通文件；超出目录或非法引用拒绝加载。
- 验证：覆盖首次/重复/变化指纹、Ed25519 创建与复用、私钥不明文落库和越界引用拒绝；Java 后端全量 41 个测试通过，其中 14 个 POSIX 权限测试按 Windows 环境预期跳过。

## 任务 7：任务状态、受控并发与 SSE

- 状态：已完成。
- 状态模型：建立 `jobs`、`job_steps`、`job_step_nodes` 和 `events` 的 JPA 实体与仓储；任务按步骤串行执行，同一步骤节点并发执行，逐级汇总 `pending/running/success/failed/interrupted` 状态。
- 并发控制：任务队列与节点工作使用两个独立的有界线程池，默认工作线程数 5、队列容量 100，避免编排线程与节点线程互相等待；队列满返回 `JOB_QUEUE_FULL` 和中文“任务队列已满，请稍后重试”。
- 提交安全：任务定义在落库前完成集群、节点、步骤顺序和重复节点校验；持久化或入队失败时级联清理已创建任务，避免孤立 `pending` 记录。
- 重启恢复：应用启动时把遗留 `running` 任务标记为 `interrupted`，不自动重复执行；`pending` 和已结束任务保持原状态。
- SSE：事件先持久化再推送，按自增 ID 保序；支持 `Last-Event-ID` 请求头和 `last_id` 查询参数断线续传，默认 15 秒心跳，终态事件后完成连接。
- 查询接口：提供任务列表、任务详情、步骤和逐节点状态接口；在关闭 `open-in-view` 的情况下显式预取节点响应字段。
- 验证：覆盖并发上限、部分失败、队列拒绝、孤立任务清理、启动恢复、SSE 顺序/续传/心跳和懒加载回归；Java 后端全量 51 个测试通过，其中 14 个 POSIX 权限测试按 Windows 环境预期跳过。

## 任务 8：Java 免密配置与节点测试

- 状态：已完成。
- API：实现 `POST /api/clusters/{clusterId}/node-test` 和 `POST /api/nodes/{nodeId}/node-test`，继续返回 `202 {job_id,status}`；集群接口支持 `failed_only=true` 只重试失败节点，重复启动返回当前活动任务 ID。
- 免密流程：使用解密后的节点密码建立 Java SSH 会话，校验/记录主机指纹，以 `grep -qxF` 幂等追加集群公钥，再使用集群 Ed25519 私钥重新连接。
- 环境探测：免密复连后读取远端 `hostname`、`/etc/os-release` 和 `uname -m`，保存操作系统、版本和规范化架构 `amd64/arm64`；远端主机名仅用于诊断，不覆盖用户配置的节点名。
- 状态事件：逐节点按 `password_connecting -> key_installing -> key_verifying -> success/failed` 更新 H2 并发送 SSE；集群按全部节点结果汇总 `running/success/failed`。
- 安全与诊断：密码仅在执行线程内解密为 `char[]`，使用后清零；失败消息包含节点、中文阶段名称、稳定阶段键和脱敏原因，密码、密文与私钥均不会进入持久化消息或运行时日志；修改密码只使测试状态失效，不清除已信任主机指纹，只有 IP 或 SSH 端口变化才重新建立指纹信任。
- 并发一致性：同一集群的测试启动使用按集群粒度的原子准入，重复请求返回现有任务 ID；启动 `running`、节点结果和集群聚合均按配置版本条件写入，配置变化后不提交旧任务，也不以旧结果覆盖 `stale`。集群密钥创建按 `clusterId` 互斥，不同集群互不阻塞；密钥锁在进入准入锁前释放，SSH 执行不持有二者。
- 验证：覆盖阶段顺序、系统信息、部分失败、失败节点重试、密码/API/SSE/运行时日志脱敏、并发启动、配置变化、集群聚合、集群密钥锁隔离、集群/单节点 API、幂等公钥命令和架构规范化；Java 后端全量 74 个测试通过，其中 14 个 POSIX 权限测试按 Windows 环境预期跳过。
