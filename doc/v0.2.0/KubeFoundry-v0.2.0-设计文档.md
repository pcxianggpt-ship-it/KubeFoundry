# KubeFoundry v0.2.0 设计文档

## 1. 版本目标

v0.2.0 将 Web 后端从 Python 迁移到 Java，并重新设计安装向导。版本目标是减少目标系统依赖、统一 SSH 能力、提升离线部署兼容性，并让用户能够沿着清晰的流水线完成 Kubernetes 集群安装。

核心变化：

1. 使用 Spring Boot 3 + Java 17 完整替换 Python 后端。
2. 使用 H2 嵌入式文件数据库，不迁移 v0.1.0 SQLite 数据。
3. 使用 Apache MINA SSHD 实现密码登录、公钥分发、免密验证、SFTP 和远程命令执行。
4. 前端采用“流水线优先”的交互结构。
5. 预检查通过后自动跳转到独立安装页，用户人工确认后启动安装。
6. 继续复用现有 `scripts/steps/` Bash 安装脚本，Java 负责配置、编排、并发、状态和日志。

整体调用链：

```text
Vue 3 + Element Plus
  -> Spring Boot REST API / SSE
  -> H2 配置与任务状态
  -> Java 任务编排器
  -> Apache MINA SSHD
  -> 远端 scripts/steps/* Bash 脚本
```

## 2. 版本范围

### 2.1 包含范围

1. Java 17 内置运行时，分别制作 x86_64 和 ARM64 离线包。
2. Spring Boot 3 后端、H2 文件数据库和数据库版本迁移。
3. 集群、节点、安装配置、任务、步骤、事件和日志管理。
4. 节点密码加密保存、复制节点、单节点测试和全部节点测试。
5. Java SSH 密码认证、公钥配置、免密验证和主机指纹校验。
6. 节点测试、预检查和安装步骤的受控并发。
7. 流水线式集群部署空间和独立安装执行页。
8. 首页按集群状态提供直接操作入口。
9. SSE 实时事件、断线续传和页面刷新后恢复任务展示。
10. 现有 Bash 安装步骤的兼容执行。

### 2.2 不包含范围

1. 用户登录、RBAC 和多租户。
2. v0.1.0 SQLite 数据迁移。
3. 后端重启后自动续跑安装任务。
4. 安装任务暂停和跨进程断点续跑。
5. 多管理节点高可用和分布式任务队列。
6. Kubernetes 升级、扩容和缩容。

## 3. 技术选型

### 3.1 Java 运行环境

后端使用 Java 17。离线包内置通过 `jlink` 生成的精简 JRE，不依赖目标系统已有 Java。x86_64 和 ARM64 分别构建、测试和发布，不在运行时下载依赖。

### 3.2 后端框架

使用 Spring Boot 3，提供：

- REST API 和统一参数校验。
- SSE 实时事件。
- 统一中文错误响应。
- 事务、任务线程池和生命周期管理。
- Java 单元测试与集成测试基础设施。

后端采用模块化单体，不引入微服务和独立消息队列。

### 3.3 数据库

使用 H2 嵌入式文件模式，数据库文件默认位于：

```text
data/kubefoundry.mv.db
```

数据库随 Spring Boot 启动，不需要单独安装或启动数据库服务。数据库结构通过版本化迁移脚本管理。

### 3.4 SSH 库

使用 Apache MINA SSHD Client，相关依赖打入应用包。后端不再依赖系统 `ssh`、`scp`、`sshpass` 或 `expect`。

## 4. 后端模块设计

```text
web/backend-java/
├── pom.xml
└── src/
    ├── main/java/io/kubefoundry/
    │   ├── api/             # REST、SSE、请求响应模型
    │   ├── cluster/         # 集群、节点和配置领域逻辑
    │   ├── credential/      # 凭据加密与主密钥管理
    │   ├── ssh/             # SSH、SFTP、主机指纹和密钥
    │   ├── job/             # 任务、步骤、事件和线程池
    │   ├── installer/       # 安装计划、脚本分发与执行
    │   └── persistence/     # H2 实体、仓储和迁移
    └── test/
```

模块职责：

- `api` 只处理协议转换和校验，不承载安装业务逻辑。
- `cluster` 管理当前配置、节点状态和部署阶段。
- `credential` 负责加密和解密，不向 API 返回明文密码。
- `ssh` 提供与具体任务无关的连接、认证、文件和命令能力。
- `job` 管理任务状态机、节点并发、事件和中断恢复标记。
- `installer` 将安装计划映射到现有 Bash 步骤。
- `persistence` 隔离 H2 访问细节。

## 5. 数据模型

### 5.1 clusters

保存集群名称、Kubernetes 版本、当前部署阶段、整体状态、配置版本和最近任务引用。

### 5.2 nodes

保存主机名、IP、角色、SSH 用户、SSH 端口、加密密码、主机指纹、操作系统、架构、免密状态和最近测试结果。

密码字段只保存密文、随机 IV 和加密版本。API 只返回 `hasPassword`，不返回密码密文或明文。

### 5.3 cluster_settings

保存网络、镜像仓库、NFS、安装介质路径、节点并发数和安装组件开关。

### 5.4 ssh_keys

每个集群拥有独立 SSH 密钥对。记录公钥、加密私钥引用、算法、创建时间和轮换时间。

### 5.5 jobs

保存节点测试、预检查和安装任务。状态枚举：

```text
pending / running / success / failed / interrupted
```

### 5.6 job_steps

保存任务阶段、目标范围、并发策略、状态、开始结束时间、退出码和错误摘要。

### 5.7 job_step_nodes

保存步骤在每个节点上的状态、时间、退出码、日志路径和错误摘要。

### 5.8 events

保存供 SSE 推送的结构化事件。事件具有递增 ID，客户端重连时使用最后事件 ID 继续读取。

### 5.9 schema_history

记录数据库迁移版本、校验值和执行时间。

## 6. 凭据安全

节点密码使用 Java 标准加密能力实现 AES-256-GCM：

1. 首次启动生成主密钥，保存到 `data/secrets/master.key`。
2. 主密钥文件仅允许后端服务账户读取。
3. 每条密码使用独立随机 IV。
4. 数据库不保存主密钥。
5. 数据库备份和主密钥备份必须分别管理，恢复时两者缺一不可。
6. 密码、私钥和完整认证参数不得写入日志、SSE、配置快照或错误响应。

复制节点时复制 SSH 用户、端口和加密密码，但清空以下字段：

- 主机名和 IP，或设置为明确的待编辑值。
- SSH 主机指纹。
- 免密状态。
- 操作系统与架构探测结果。
- 最近节点测试状态和测试时间。

## 7. 节点测试与 SSH 免密流程

“测试全部节点”执行以下流程：

1. 校验正式节点均具有 IP、SSH 用户、端口和已保存密码。
2. 为集群创建或读取 Ed25519 密钥对。
3. 使用密码并发连接目标节点。
4. 首次连接记录主机指纹；已记录指纹发生变化时拒绝连接。
5. 读取远端 `authorized_keys`，不存在集群公钥时追加写入。
6. 断开密码连接，使用集群私钥重新登录。
7. 探测主机名、操作系统、版本和架构。
8. 保存逐节点结果并汇总任务状态。

节点测试状态：

```text
pending             等待测试
password_connecting 密码连接中
key_installing      正在配置公钥
key_verifying       正在验证免密
success             测试成功
failed              测试失败
stale               配置已变更，结果失效
```

前端只显示中文文案，API 和数据库使用稳定英文枚举。

默认节点并发数为 5，可在系统设置中调整。单个节点失败不回滚已成功节点；支持只重试失败节点。日志记录节点、阶段和可操作的错误原因。

## 8. 任务与并发模型

任务创建接口立即返回 `jobId`，实际工作由受控线程池执行。线程池必须设置最大线程数和队列长度，禁止按请求无限创建线程。

执行原则：

1. 安装步骤之间默认串行。
2. 同一步骤可按节点并发。
3. 安装依赖、环境配置、containerd 和部分验证步骤允许并发。
4. 控制面初始化、控制节点加入和依赖 Kubernetes API 的关键步骤保持串行。
5. 每个节点独立记录状态、标准输出、标准错误和退出码。
6. 并发步骤完成后统一汇总，决定是否进入下一步骤。

后端启动时，将数据库中仍为 `running` 的任务标记为 `interrupted`。v0.2.0 不自动续跑，以避免重复执行系统操作；用户可以查看已完成日志并创建新的重试任务。

## 9. API 设计

尽量保持 v0.1.0 `/api/*` 路径和响应结构，降低前后端同时迁移的风险。

核心接口：

```text
GET    /api/clusters
POST   /api/clusters
GET    /api/clusters/{clusterId}
PUT    /api/clusters/{clusterId}
DELETE /api/clusters/{clusterId}

GET    /api/clusters/{clusterId}/workspace
GET    /api/clusters/{clusterId}/nodes
POST   /api/clusters/{clusterId}/nodes
PUT    /api/nodes/{nodeId}
DELETE /api/nodes/{nodeId}
POST   /api/clusters/{clusterId}/nodes/copy

POST   /api/clusters/{clusterId}/node-test
POST   /api/nodes/{nodeId}/node-test
POST   /api/clusters/{clusterId}/precheck
POST   /api/clusters/{clusterId}/install

GET    /api/jobs/{jobId}
GET    /api/jobs/{jobId}/execution
GET    /api/jobs/{jobId}/steps
GET    /api/jobs/{jobId}/events
GET    /api/job-step-nodes/{itemId}/log
```

错误响应统一包含稳定错误码、中文消息和可选字段级错误，不返回 Java 堆栈。

## 10. SSE 事件

事件类型：

```text
job.status
step.status
node.status
log.line
precheck.result
```

客户端断线后携带最后事件 ID 重连。安装执行页刷新时，先读取任务当前快照，再建立 SSE 连接，避免页面只依赖内存事件恢复状态。

## 11. 前端信息架构

### 11.1 首页

首页展示集群列表。主要按钮根据集群状态直接定位用户当前需要处理的内容：

| 集群状态 | 首页主要操作 | 目标页面 |
| --- | --- | --- |
| 配置未完成 | 继续配置 | 当前未完成阶段 |
| 预检查已通过 | 开始安装 | 安装确认页 |
| 正在安装 | 查看进度 | 安装执行页 |
| 安装失败 | 查看失败原因 | 失败步骤与日志 |
| 安装成功 | 查看集群 | 集群概览 |

用户点击集群名称进入完整部署空间，但查看运行任务不需要先进入集群再点击流水线。

### 11.2 集群部署流水线

单个集群使用五阶段横向流水线：

```text
01 集群信息
02 服务器节点
03 安装配置
04 部署预检查
05 执行安装
```

页面始终显示当前阶段、已完成阶段、阻塞原因和下一步。已完成阶段允许返回修改；修改关键配置后，后续相关阶段标记为“需要重新验证”。每个阶段只保留一个主要操作。

### 11.3 节点配置页

节点配置页使用高密度表格，提供：

- 添加节点、编辑节点、删除节点和复制所选。
- 角色、状态和关键词筛选。
- SSH 用户、端口、密码配置状态和节点测试状态。
- “测试全部节点”主要操作。
- 逐节点免密配置进度和可操作错误提示。

### 11.4 预检查与安装页

预检查全部通过后自动跳转到独立安装确认页，但不自动启动安装。

安装确认页展示目标集群、Kubernetes 版本、节点数量、关键配置和风险提示。用户点击“开始安装”后进入任务执行视图。

执行视图展示：

- 整体任务状态和运行时间。
- 安装阶段列表。
- 每个节点的当前步骤、状态和进度。
- 全部日志和按节点过滤的实时日志。
- 失败节点、失败步骤和错误原因。

路由建议：

```text
/clusters/{clusterId}/install
/jobs/{jobId}/execution
```

## 12. 视觉与交互规范

前端继续使用 Vue 3 + Element Plus，采用流水线优先的运维界面：

1. 信息密度适中，避免装饰性首页、卡片堆叠和过度留白。
2. 使用平面表格、清晰分隔线和稳定的间距尺度。
3. 主色使用克制的青绿色，成功、警告和失败使用语义色。
4. 状态必须同时包含图标或文字，不只依赖颜色。
5. 所有按钮、表单、加载、空数据、禁用和错误状态完整实现。
6. 支持键盘操作和可见焦点，达到 WCAG 2.1 AA 基本要求。
7. 验证 320px、768px、1024px 和 1440px 视口；运维表格在窄屏允许受控横向滚动。
8. 可见状态和错误消息统一使用中文。

## 13. Bash 脚本兼容策略

Java 编排器继续使用现有 `scripts/steps/`：

1. 为任务生成 `runtime.env` 和配置快照。
2. 使用 SFTP 分发运行环境和当前步骤脚本。
3. 远端执行 `bash -lc 'source runtime.env && bash step.sh'`。
4. 收集标准输出、标准错误和退出码。
5. 更新任务、步骤和节点状态。

Bash 脚本仍负责具体系统命令、配置修改、服务管理和步骤内校验。Java 负责节点选择、依赖顺序、并发、重试、状态和日志。

## 14. 日志与错误处理

本地日志路径：

```text
data/jobs/{jobId}/logs/job.log
data/jobs/{jobId}/logs/{stepKey}.log
data/jobs/{jobId}/logs/{stepKey}/{hostname}.log
```

错误必须区分连接失败、认证失败、主机指纹变化、公钥写入失败、命令超时、脚本退出失败和后端内部错误。前端消息需要说明发生了什么以及建议如何处理。

任何日志和错误响应不得包含节点密码、主密钥、集群私钥或完整认证参数。

## 15. 离线打包

每个架构的离线包包含：

```text
runtime/               精简 JRE 17
app/kubefoundry.jar    Spring Boot 后端
web/                   前端静态资源
scripts/               Bash 安装步骤
config/                默认配置
deploy.sh              服务安装与启动脚本
```

构建阶段固定 Maven 和 npm 依赖版本。发布前分别在 x86_64 和 ARM64 信创环境验证 JRE、H2、Apache MINA SSHD、SFTP、SSE 和安装脚本执行。

## 16. 测试策略

1. Java 单元测试覆盖加密、状态机、安装计划和错误映射。
2. H2 集成测试覆盖事务、数据库迁移和后端重启后的任务中断标记。
3. SSH 测试服务器覆盖密码认证、公钥安装、重复安装、指纹变化和认证失败。
4. API 契约测试保证关键 v0.1.0 接口结构兼容。
5. Vue 组件测试覆盖流水线、中文状态、首页直接入口和安装页恢复。
6. 浏览器测试覆盖预检查跳转、人工确认、SSE 断线重连和失败日志定位。
7. x86_64、ARM64 离线包分别执行安装和启动冒烟测试。

## 17. 验收标准

1. 目标系统没有 Python、`sshpass` 和系统 Java 时，离线包仍可启动。
2. 可以创建集群、配置节点并加密保存密码。
3. 复制节点时复制登录凭据，但不会复制免密和测试状态。
4. “测试全部节点”可以并发配置 SSH 免密，并显示逐节点中文状态。
5. 主机指纹变化时拒绝连接并给出明确提示。
6. 预检查成功后自动进入安装确认页，安装不会自动启动。
7. 安装启动后可查看阶段、节点进度和实时日志。
8. 首页可一次点击进入正在运行任务的进度页。
9. 页面刷新和 SSE 重连后可以恢复任务展示。
10. 后端重启后运行中任务标记为已中断，不会自动重复执行。
11. 现有 Bash 核心安装步骤可由 Java 编排器执行。
12. x86_64 和 ARM64 离线包均通过冒烟验证。
## 18. 安装后配置锁定

安装任务创建成功后，集群进入配置锁定状态。锁定是后端规则，不依赖前端页面：集群信息、节点新增编辑删除复制和集群安装配置的修改请求均返回 `409 / CLUSTER_CONFIGURATION_LOCKED`。

锁定持续到用户主动执行 `POST /api/clusters/{clusterId}/reset`。重置不会删除节点、安装配置、历史任务或日志，但会将集群恢复为草稿、解除配置锁定，并使全部节点测试结果失效；用户需要重新测试节点和执行预检查后才能再次安装。安装进行中存在活动安装或预检查任务时，重置请求会被拒绝。

安装任务无论成功、失败或中断，均保留独立执行页及其快照、阶段、节点诊断和日志。已完成集群的首页操作直接进入该执行页，工作区的“执行安装”阶段也会复用最近一次安装任务的执行页。
