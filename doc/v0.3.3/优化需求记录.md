## 3. 待办需求清单

### 3.1 `/etc/resolv.conf` 保留已有 DNS，缺失时兜底

- [x] 如果 `/etc/resolv.conf` 已存在且配置了 `nameserver`，则不修改该文件。
- [x] 如果文件不存在，或文件中没有 `nameserver` 配置，则添加一条 `nameserver 8.8.8.8`。
- [x] 注释中的 `nameserver` 和未填写地址的指令不算已有配置；保留其他内容，兼容无末尾换行和符号链接，重复执行不重复追加。
- [x] 读取或写入失败时输出明确错误并中止，不报告配置成功。

实现位置为 `scripts/steps/phase2_k8s_base/15-environment-config.sh`，在全部节点的环境配置步骤执行。同键验证脚本 `scripts/verify/phase2_k8s_base/verify-15-environment-config.sh` 已增加只读 DNS 检查，避免前置验证跳过缺少 DNS 的节点。

本地验证：WSL Linux 的 DNS/sysctl 回归测试、受管配置测试通过。验证脚本契约检查在原有 Redis 验证脚本的非交互 `read` 循环处误判失败，未修改该脚本。尚未在真实节点验证 CoreDNS 启动。

此变更补充缺失的上游 DNS，避免 CoreDNS 因没有上游服务器而启动失败；不检查已有 DNS 地址的可达性，也不启动或重启 `systemd-resolved`。DNS 配置为追加操作，不加入受管配置清理，集群重置时保留。

回归用例位于 `scripts/tests/test_environment_sysctl.sh`，覆盖文件缺失、空文件、注释、空指令、已有 IPv4/IPv6、多条 DNS、缩进、无末尾换行、符号链接、幂等性、读写失败及前置验证返回码。

### 3.2 重置集群时清理已有容器

- [ ] 重置集群时，先删除 `nerdctl ps -a` 列出的所有已创建容器。
- [ ] 避免重新安装 Kubernetes 时，因使用相同容器名称而提示容器已经存在。

### 3.3 非 root 用户执行命令时使用 sudo

- [ ] 使用非 root 用户安装时，每个执行命令前均需添加 `sudo`。

### 3.4 非 root 用户安装前检查 sudo 权限

- [ ] 使用非 root 用户安装时，在测试集群连通性环节增加 `sudo` 权限检查。
- [ ] 非 root 用户不满足 `sudo` 权限要求时，不允许开始安装。

### 3.5 新增“集群恢复及重置”模块

- [ ] 新增“集群恢复及重置”功能模块。
- [ ] 将集群安装模块中现有的集群重置功能迁移到该模块。
- [ ] 支持根据 etcd 备份文件，将集群恢复到指定版本。

### 3.6 Shell 脚本简化与全面审核

- [ ] 全面审核现有 Shell 脚本，检查脚本中的方法定义、方法调用及其对阅读和维护的影响。
- [ ] 减少不必要的命令封装，使脚本整体风格更接近手动执行命令的方式。
- [ ] 对简单命令直接在执行位置书写，例如直接使用 `kubectl apply -f`，不再为简单命令额外封装方法。
- [ ] 在简化脚本的同时，保留确有复用价值或承载完整逻辑的必要方法。

### 3.7 组件补装支持安装未安装过的组件

- [ ] 优化组件补装功能，使其不局限于集群配置中已经配置的组件。
- [ ] 支持选择并安装当前集群中尚未安装过的组件。
