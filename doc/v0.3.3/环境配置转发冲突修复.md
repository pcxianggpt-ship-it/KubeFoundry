# 环境配置转发冲突修复

## 故障原因

`sysctl --system` 加载独立配置后，还会加载 `/etc/sysctl.conf`。原有 `net.ipv4.ip_forward=0` 会覆盖 KubeFoundry 的设置，导致配置脚本成功但后置验证失败。

## 修复行为

保留 `/etc/sysctl.d/99-kubefoundry-k8s.conf`，同时在 `/etc/sysctl.conf` 末尾维护 `KubeFoundry sysctl` 标记块，设置 IPv4 转发及桥接 IPv4/IPv6 iptables 参数为 1。保留用户原始配置；重复运行只更新标记块。符号链接形式的 `/etc/sysctl.conf` 或损坏的标记块会被拒绝，需管理员检查后处理。

加载错误或读取错误会中止安装，只有三个必需参数均为 1 才报告成功。后置验证读取失败返回 20，参数不符合要求返回 10。

节点重置预检查包含此标记块；清理时只移除标记块并重新加载系统配置，原有参数重新生效。不要仅通过 `sysctl -w` 临时修复，否则重新加载后仍可能回退。

## 验证

运行 `bash scripts/tests/test_environment_sysctl.sh`，覆盖原配置为 0、重复执行、加载失败、读取失败、实际值错误、移除标记块恢复原文件，以及验证退出码。

## 现场验证（2026-09-27）

玫瑰园网络三台节点 k8sc1、k8sw1、k8sw2 已应用标记块并重新加载全部 sysctl 配置，三个必需参数均为 1，环境验证退出码均为 0。此次未重启节点，未重跑完整安装。原始配置备份保存在各节点 `/var/tmp/kubefoundry-sysctl-backup.*/sysctl.conf`。

Linux 节点通过四项回归：`test_environment_sysctl.sh`、`test_managed_config_ownership.sh`、`test_reset_component_cleanup.sh`、`test_verify_contract.sh`。Sol 专项复核因额度限制未完成。
