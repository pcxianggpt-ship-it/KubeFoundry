# KubeFoundry v0.2.1 部署手册

## 发布包

发布包按 CPU 架构独立生成：

```text
kubefoundry-web-v0.2.1-x86_64.tar.gz
kubefoundry-web-v0.2.1-aarch64.tar.gz
```

包内包含 Java 17 精简运行时、后端 JAR、前端静态文件、安装步骤和 `${APP_DIR}/kube-media` 离线介质目录。目标服务器无需安装 Java、Python、Node.js、Maven、npm 或 `sshpass`。

## 构建

构建机需要 Bash、tar、sha256sum、JDK 17（含 `jlink`）、Maven 3.8+、Node.js 18+ 和 npm。

```bash
KF_TARGET_ARCH=x86_64 KF_JAVA_HOME=/opt/jdk-17 bash package.sh
KF_TARGET_ARCH=aarch64 KF_JAVA_HOME=/opt/jdk-17-aarch64 bash package.sh
```

交叉构建 ARM64 时，增加 `KF_TARGET_JDK_HOME` 并指向真实 ARM64 JDK 17。构建前，将当前架构的离线介质放入仓库根目录 `kube-media/`；预检查会继续校验实际需要的介质文件。

## 部署

在目标服务器上选择与 `uname -m` 一致的发布包：

```bash
mkdir -p /opt/kubefoundry
cd /opt/kubefoundry
tar -xzf kubefoundry-web-v0.2.1-x86_64.tar.gz
cp kubefoundry-web-v0.2.1-x86_64/deploy.sh .
sudo bash deploy.sh kubefoundry-web-v0.2.1-x86_64.tar.gz
```

默认端口为 `10001`，可使用 `--port` 指定其他端口。脚本会校验包内清单、符号链接和运行时架构，再安装 systemd 服务。

## 目录与升级

| 目录 | 内容 | 升级策略 |
| --- | --- | --- |
| `app/` | JRE、JAR 和前端 | 每次部署替换 |
| `kube-media/` | 当前版本离线介质 | 每次部署替换 |
| `scripts/` | 远端安装和验证脚本 | 每次部署替换 |
| `data/` | H2、主密钥、凭据和任务数据 | 永久保留，权限 `0700` |
| `logs/` | 应用和部署日志 | 永久保留，权限 `0700` |

升级前备份 `data/`。H2 迁移只向前兼容；回退前必须在备份副本中验证旧版本兼容性。

## 验证

```bash
curl -fsS http://127.0.0.1:10001/api/health
sudo bash deploy.sh --status
```

真实 x86_64 与 ARM64 启动和非破坏性预检查需要分别在对应架构的专用测试环境完成。
