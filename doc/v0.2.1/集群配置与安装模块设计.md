# KubeFoundry v0.2.1 集群配置与安装模块设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.2.1 |
| 状态 | 设计稿 |
| 日期 | 2026-07-29 |
| 适用范围 | Vue 3 前端、Java 17 后端、H2/Flyway、Bash 安装与重置脚本 |

## 2. 背景与目标

v0.2.0 将集群信息、服务器节点、安装配置、预检查和安装执行放在同一个“集群部署”流水线中。该结构混合了配置管理与高风险远程操作，节点角色也只能单选，无法覆盖镜像仓库与 Kubernetes 节点部署在同一台服务器上的实际场景。

v0.2.1 的目标如下：

1. 将“集群部署”拆分为同级的“集群配置”和“集群安装”两个模块。
2. 集群配置模块只管理配置并提供配置预检查，不直接启动安装或重置。
3. 集群安装模块负责预检查、安装执行、执行记录和远程重置。
4. 安装成功后持久锁定相关配置；远程重置全部成功后解锁。
5. 节点支持多角色，并由唯一的镜像仓库角色节点提供仓库主机名和 IP。
6. 收敛安装参数，只允许配置 Kubernetes 工作目录，其余路径由系统派生。
7. Pod 和 Service 网段改为安装脚本固定值，Java 不再保存、读取或注入这两个值。
8. 本版本提供 Kubemate 组件配置页面和配置持久化，但不参与实际安装。

## 3. 范围与非目标

### 3.1 本版本范围

- 一级导航和路由拆分。
- 集群信息、服务器节点、Kubemate 组件和配置预检查页面调整。
- Kubernetes 版本选择框。
- 节点多角色数据模型、接口和校验。
- 镜像仓库类型配置，当前仅允许 Registry 通过预检查。
- Registry 节点信息派生。
- 安装状态机和配置锁定时机调整。
- 独立远程重置任务、强确认、日志和失败重试。
- 安装路径固定规则和离线介质目录解析。
- 数据库迁移、自动化测试和中文文档同步。

### 3.2 非目标

- Harbor 的实际安装。
- Loki、Traefik、NFS 等 Kubemate 组件的实际安装。
- Kubemate 组件依赖关系、参数表单和 phase3 安装编排。
- 动态发现任意 Kubernetes 版本。
- 修改固定 Pod/Service 网段的能力。
- 重置 KubeFoundry 管理端自身或删除历史任务日志。

## 4. 总体信息架构

应用侧边栏调整为：

```text
集群配置
集群安装
```

集群配置模块内的顺序为：

```text
01 集群信息
02 服务器节点
03 Kubemate 组件
04 配置预检查
```

集群信息首页集中保存名称、说明、版本、网络固定值说明、镜像仓库类型和 Kubernetes 工作目录，不再设置独立“安装配置”阶段。

配置预检查通过后，“下一步”进入同一集群的集群安装模块。集群安装模块的顺序为：

```text
01 安装概览
02 安装预检查
03 安装确认
04 安装执行/执行记录
05 远程重置
```

配置模块和安装模块复用同一个预检查后端能力。配置模块用于完成配置验收，安装模块展示最近一次预检查结果并允许重新执行，不建立第二套预检查数据。

## 5. 集群信息设计

### 5.1 可配置字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 集群名称 | 文本 | 必填，集群内唯一标识沿用现有规则 |
| 说明 | 多行文本 | 可选，最长 500 字 |
| Kubernetes 版本 | 选择框 | 当前只有 `1.30.14` |
| 镜像仓库类型 | 选择框 | 值域预留 `REGISTRY`、`HARBOR`；当前仅 `REGISTRY` 可用 |
| Kubernetes 工作目录 | 绝对路径 | 必填，默认 `/data/k8s_install` |

Harbor 选项在页面中显示“暂未支持”并禁用。后端仍需在保存、预检查和安装准入时校验当前仅支持 `REGISTRY`，防止绕过前端。

### 5.2 固定网络参数

Pod 和 Service 网段不再作为集群配置字段：

```text
Pod 网段:     10.244.0.0/16
Service 网段: 10.96.0.0/16
```

Java 后端应删除以下职责：

- 不再从集群请求和响应中处理 `pod_subnet`、`service_subnet`。
- 不再从数据库实体读取这两个字段。
- 不再通过 `RuntimeEnvRenderer` 注入 `KF_POD_SUBNET`、`POD_SUBNET`、`KF_SERVICE_SUBNET`、`SERVICE_SUBNET`。

Bash 安装脚本在需要处定义只读常量，禁止从外部环境覆盖：

```bash
readonly POD_SUBNET="10.244.0.0/16"
readonly SERVICE_SUBNET="10.96.0.0/16"
```

涉及脚本至少包括 Kubernetes 初始化和 Flannel 安装。验证脚本应使用相同固定值进行验证，避免配置和验证基线不一致。

### 5.3 路径派生规则

用户只配置 Kubernetes 工作目录。所有派生路径在 Java 运行时统一计算，不保存为独立配置：

```text
kubernetes_work_dir = 用户配置值
kubelet_root        = ${kubernetes_work_dir}/kubelet_root
etcd_data_dir       = ${kubernetes_work_dir}/etcd_root
containerd_root     = ${kubernetes_work_dir}/containerd_root
```

Containerd 安装阶段将解析 `.env.containerd_root`（未配置时使用上述派生值），创建该目录，并写入 `/etc/containerd/config.toml` 的顶层 `root` 字段；不得继续使用镜像模板中的默认目录。

应用目录以 systemd 的 `WorkingDirectory=${APP_DIR}` 为基准：

```text
install_media = ${APP_DIR}/kube-media
repo_source   = ${APP_DIR}/kube-media/01.rpm_package/k8srepo_kylinos_sp3_${arch}.tar.gz
```

`${APP_DIR}` 必须由后端在启动时解析为规范化绝对路径。不得通过前端、集群 API 或全局设置 API 覆盖。远端分发仍由 Java 安装编排器完成，目标节点不要求存在相同的本地应用路径。

路径校验包括：

- Kubernetes 工作目录必须为 Linux 绝对路径。
- 不允许 `/`、`/etc`、`/usr`、`/boot` 等高风险系统目录。
- 禁止包含换行、NUL、Shell 控制字符和未解析变量。
- 安装和重置均使用规范化后的同一份路径快照。
- 本地离线介质、仓库源包和当前架构所需文件必须在预检查阶段存在且为普通文件或目录。

## 6. 服务器节点与多角色

### 6.1 角色模型

节点角色从单值 `role` 调整为集合 `roles`：

```json
{
  "roles": ["control_plane", "registry"]
}
```

支持的角色：

- `control_plane`：控制节点。
- `worker`：工作节点。
- `registry`：镜像仓库节点。

允许组合：

- `control_plane`
- `worker`
- `registry`
- `control_plane + registry`
- `worker + registry`

禁止同一节点同时拥有 `control_plane` 和 `worker`。

### 6.2 数据库存储

不使用逗号字符串或 JSON 字符串保存角色。新增关系表：

```text
node_roles
├── node_id
├── role
└── UNIQUE(node_id, role)
```

迁移时把现有 `nodes.node_role` 写入 `node_roles`。在完成实体、查询和接口切换后再决定是否删除旧列；同一版本内可以保留旧列作为只读兼容字段，但新逻辑只能以关系表为权威来源。

### 6.3 镜像仓库信息派生

删除集群信息中的镜像仓库主机名、IP、端口字段。运行时按如下规则获得仓库信息：

```text
registry_hostname = 唯一 registry 角色节点的 hostname
registry_ip       = 唯一 registry 角色节点的 IPv4
registry_port     = 固定 5000
```

生成的 `/etc/hosts` 需将 `registry_ip` 同时映射到该节点主机名和固定别名 `registry`，以保证集群内可通过 `registry` 解析镜像仓库。`kubeadm` 的 `imageRepository` 固定使用 `registry:5000/registry.k8s.io`，与 containerd 的 `certs.d/registry:5000` 保持一致。

Registry 可以和控制节点或工作节点同机。安装目标解析必须使用角色集合包含关系，不能再使用字符串相等判断。

### 6.4 拓扑校验

统一的集群拓扑校验器必须同时供配置预检查、安装预检查和安装准入使用：

1. 同一节点不能同时配置控制节点和工作节点角色。
2. 全集群最多一个节点包含镜像仓库角色。
3. 控制节点数量仅支持 1 个或 3 个。
4. 至少一个工作节点。
5. 当前仓库类型为 Registry 时，必须恰好一个镜像仓库节点。
6. 当前版本仓库类型必须为 `REGISTRY`。
7. 节点主机名和 IPv4 在同一集群内不得重复。
8. 参与操作的节点必须完成节点测试且状态为 `success`。

单节点角色冲突在节点保存时立即拒绝；控制节点、工作节点和镜像仓库的全局数量在预检查和安装准入时校验，以允许用户分步骤录入节点。

## 7. Kubemate 组件配置

### 7.1 页面范围

本版本新增 Kubemate 组件页面，提供：

- “启用 Kubemate 组件”总开关。
- Loki、Traefik、NFS 等组件的独立开关。
- 明确提示：“v0.2.1 仅保存组件选择，不执行组件安装；实际安装将在 v0.3.0 提供。”

总开关关闭时，子组件开关保持已保存值但界面禁用；重新打开后恢复此前选择。

### 7.2 持久化

建议新增集群组件配置表：

```text
cluster_components
├── cluster_id
├── component_key
├── enabled
└── UNIQUE(cluster_id, component_key)
```

也可以为总开关使用集群级 `kubemate_enabled` 字段。组件键使用稳定英文枚举，可见名称使用中文。

### 7.3 安装隔离

v0.2.1 的 `InstallPlanFactory` 不得读取 Kubemate 组件配置，不得把 `phase3_ecosystem` 步骤加入安装计划。安装确认页可以展示“已保存，当前版本不安装”的只读摘要，但不能宣称这些组件将随集群安装。Kubemate 组件实际安装统一纳入 v0.3.0。

## 8. 配置预检查

配置预检查由以下检查组成：

1. 集群信息完整性。
2. Kubernetes 版本必须为 `1.30.14`。
3. 仓库类型必须为 `REGISTRY`。
4. 节点多角色拓扑校验。
5. 全部节点测试状态校验。
6. 远程节点 CPU、内存、磁盘、系统、架构和端口检查。
7. 配置的离线介质目录必须在管理节点存在，并检查其当前架构介质完整性。
8. Kubernetes 工作目录安全性和目标节点可创建性检查。

预检查结果与触发时的配置版本绑定。修改集群信息、节点角色、节点连接信息、Kubemate 配置或 Kubernetes 工作目录后，最近一次预检查标记为失效。Kubemate 配置虽然不参与安装，本版本仍按统一配置版本处理，以保证页面状态一致。

## 9. 集群安装模块

### 9.1 安装准入

启动安装必须满足：

- 不存在同集群的活动预检查、安装或重置任务。
- 最近一次预检查成功且对应当前配置版本。
- 节点测试状态仍然有效。
- 再次通过拓扑、仓库类型、版本和介质校验。
- 用户在安装确认页完成风险确认。

### 9.2 安装配置快照

安装任务创建时保存不可变快照，至少包含：

- 集群名称和 Kubernetes 版本。
- Kubernetes 工作目录及派生目录。
- 应用目录和离线介质路径。
- 节点 ID、主机名、IP、SSH 信息引用和角色集合。
- 唯一 Registry 节点信息。
- 固定 Pod/Service 网段版本标识。

运行中的所有步骤只读取任务快照，避免用户修改或后端重启导致同一任务使用不同参数。快照不得包含明文密码、私钥或密文内容。

## 10. 安装锁定状态机

安装成功后才设置持久配置锁。安装运行期间使用活动任务守卫临时禁止配置修改。

| 当前状态 | 事件 | 新状态 | 持久配置锁 |
| --- | --- | --- | --- |
| `draft/precheck_passed/install_failed` | 安装任务接受 | `installing` | 不设置；活动任务期间禁止修改 |
| `installing` | 安装成功 | `installed` | 锁定 |
| `installing` | 安装失败 | `install_failed` | 不锁定 |
| `installed` | 重置任务接受 | `resetting` | 保持锁定 |
| `resetting` | 全部重置成功 | `draft` | 解锁 |
| `resetting` | 重置失败或中断 | `reset_failed` | 保持锁定 |
| `reset_failed` | 重试成功 | `draft` | 解锁 |

当存在 `pending/running` 的预检查、安装或重置任务时，后端统一拒绝集群配置写操作。前端禁用只用于改善体验，后端才是权威约束。

## 11. 远程重置设计

### 11.1 操作语义

现有同步 `POST /api/clusters/{clusterId}/reset` 只修改数据库状态，必须替换为异步远程重置任务。重置不会删除集群配置、节点、任务历史和日志，但会清理目标服务器上的 Kubernetes 安装结果，并在全部目标成功后解除配置锁。

安装失败或中断后也允许发起远程重置，以清理部分安装残留；如果集群原本已经锁定，重置失败时保持锁定。

### 11.2 强确认

前端必须同时满足：

1. 展示将影响的节点、目录和不可恢复风险。
2. 用户勾选“我已了解远程集群数据将被清理”。
3. 用户手工输入 `RESET <集群名称>`。
4. 确认按钮在文本完全匹配前保持禁用。

后端必须重新校验确认短语，不能只依赖前端：

```json
{
  "acknowledged": true,
  "confirmation_phrase": "RESET production-cluster"
}
```

确认失败返回 `400 / RESET_CONFIRMATION_MISMATCH`。

### 11.3 重置准入

- 集群至少存在一次已接受的安装任务。
- 不存在活动预检查、安装或重置任务。
- 使用最近一次安装任务快照确定目标，不能使用可能已变化的页面表单临时拼装目标。
- 所有目标路径必须经过规范化和安全边界校验。
- 任务创建和活动任务检查必须在集群级事务锁内完成。

### 11.4 重置步骤

重置脚本按角色集合选择目标，建议顺序如下：

1. 记录快照并验证所有目标节点身份。
2. 工作节点执行 `kubeadm reset -f` 和 Kubernetes 网络清理。
3. 非主控制节点执行相同清理。
4. 主控制节点最后执行重置和 etcd 数据清理。
5. Registry 角色执行本项目创建的 Registry 容器和相关配置清理；同机多角色节点只建立一条节点执行记录，但按步骤执行对应动作。
6. 清理本项目管理的 kubelet、etcd、containerd 数据目录。
7. 验证 kubelet 已停止、Kubernetes 配置已清除、受管容器已移除。
8. 全部节点成功后更新集群为 `draft`、解除持久锁，并把节点测试与配置预检查标记为失效。

具体脚本必须满足：

- 幂等：资源已经不存在时视为成功。
- 只清理明确白名单路径，不接受任意客户端传入路径。
- 不清理 `${APP_DIR}/kube-media`、KubeFoundry 数据库、任务日志、SSH 密钥和用户配置。
- 不使用未校验的通配符或空变量执行递归删除。
- 每个危险目录删除前再次确认其位于任务快照的 Kubernetes 工作目录内。
- 每个节点保存标准输出、标准错误、退出码和失败原因。

### 11.5 失败与重试

任一节点失败时任务状态为 `failed`，集群状态为 `reset_failed`。如果集群此前已锁定则继续锁定，不允许通过单独数据库接口解锁。用户修复 SSH、主机状态或残留资源后，可使用同一强确认机制重新执行；幂等脚本跳过已经完成的清理。

应用重启时，运行中的重置任务标记为 `interrupted`，集群进入 `reset_failed` 并保持原锁定状态，禁止自动继续执行破坏性操作。

## 12. API 调整

建议接口如下：

```text
GET  /api/clusters
POST /api/clusters
GET  /api/clusters/{clusterId}
PUT  /api/clusters/{clusterId}

GET  /api/clusters/{clusterId}/nodes
POST /api/clusters/{clusterId}/nodes
PUT  /api/nodes/{nodeId}

GET  /api/clusters/{clusterId}/components
PUT  /api/clusters/{clusterId}/components

POST /api/clusters/{clusterId}/precheck
POST /api/clusters/{clusterId}/install
POST /api/clusters/{clusterId}/reset

GET  /api/jobs/{jobId}
GET  /api/jobs/{jobId}/events
GET  /api/jobs/{jobId}/logs
```

调整点：

- 集群请求和响应删除 Pod/Service 网段以及 Registry 主机名、IP、端口。
- 集群请求新增 `kubernetes_work_dir` 和 `image_registry_type`。
- 节点请求和响应把 `role` 改为 `roles` 数组。
- 重置接口返回 `202 Accepted` 和 `job_id`，不再同步返回已解锁集群。
- `job_type` 新增 `reset`。
- 活动任务冲突沿用稳定错误结构，并覆盖 reset 类型。

## 13. 数据迁移

必须新增 Flyway 迁移，不修改 V1 至 V7：

1. 为集群增加 Kubernetes 工作目录和镜像仓库类型字段。
2. 新增 `node_roles` 并迁移现有单角色。
3. 新增 Kubemate 组件配置表。
4. 新增安装任务配置快照存储。
5. 将历史 `registry_ip` 对应节点补充 Registry 角色；无法匹配时保留迁移告警并要求重新配置。
6. 新代码停止读取旧 Pod/Service 和 Registry 三字段。
7. 旧字段先停止使用，确认兼容窗口和数据回滚方案后再在后续迁移删除。
8. 修正 V7 的历史锁定语义：仅确有成功安装任务的集群保持持久锁，失败或中断任务不应被回填为安装成功锁定。

## 14. 前端路由与交互

建议路由：

```text
/cluster-config
/cluster-config/{clusterId}/info
/cluster-config/{clusterId}/nodes
/cluster-config/{clusterId}/components
/cluster-config/{clusterId}/precheck

/cluster-install
/cluster-install/{clusterId}/overview
/cluster-install/{clusterId}/precheck
/cluster-install/{clusterId}/confirm
/jobs/{jobId}/execution
/cluster-install/{clusterId}/reset
```

每个配置阶段提供“上一步”和“保存并下一步”。保存失败不得跳转。配置预检查成功后的“下一步”跳转到对应集群的安装概览。

锁定集群仍允许查看配置和组件选择，但所有修改操作禁用，并显示“安装成功后配置已锁定，完成远程重置后可修改”。

## 15. 安全与审计

- 安装、预检查和重置使用同一个集群级活动任务互斥机制。
- 重置请求、准入、开始、每节点结果和最终状态写入事件流。
- 日志不得包含节点密码、密文、私钥或认证参数。
- Shell 参数继续使用严格单引号转义，路径只能来自后端校验后的快照。
- 删除或清理前必须校验规范化绝对路径和允许前缀。
- 重置接口不得提供“仅解锁”旁路。
- 管理端重启不得自动恢复破坏性重置任务。

## 16. 测试与验收

### 16.1 后端

- 集群 API 不再接收或返回 Pod/Service 和 Registry 三字段。
- Java runtime.env 不包含 Pod/Service 变量，Registry 信息来自唯一 Registry 节点。
- 多角色保存、查询、迁移和目标解析正确。
- 拓扑校验覆盖允许与禁止的角色组合。
- 安装失败不持久锁定，安装成功才锁定。
- 活动任务期间仍拒绝配置修改。
- 重置确认、准入、执行、部分失败、重试和成功解锁测试通过。
- 应用重启后重置任务变为 interrupted，锁状态保持安全。

### 16.2 Bash

- kubeadm 和 Flannel 使用固定网段。
- 重置脚本幂等且只清理白名单路径。
- 空工作目录、根目录、路径越界和符号链接场景被拒绝。
- 同机多角色节点不会重复创建相互冲突的节点级执行记录。

### 16.3 前端

- 两个一级模块和全部路由可刷新恢复。
- 集群信息包含版本、仓库类型和工作目录，不存在独立安装配置页。
- 节点角色支持多选并即时阻止控制节点与工作节点同时选择。
- Kubemate 页面明确标识“当前版本不执行安装”。
- 配置阶段“保存并下一步”行为正确。
- 安装成功锁定、失败可编辑、重置中和重置失败状态展示正确。
- 强确认缺少勾选或短语不匹配时不能提交。

## 17. 验收标准

1. 集群配置和集群安装作为两个同级模块独立访问。
2. 集群配置模块不能启动安装或重置。
3. Pod/Service 网段在 Java 模型和运行环境中消失，实际安装仍固定使用指定值。
4. 页面只允许选择 Kubernetes `1.30.14`。
5. 页面只配置 Kubernetes 工作目录，其余路径严格按规则派生。
6. Registry 主机名和 IP 来自唯一 Registry 角色节点，端口固定为 5000。
7. 同一服务器可以同时承担 Registry 和一种 Kubernetes 节点角色。
8. 拓扑非法时预检查和安装均被后端拒绝。
9. Kubemate 配置可保存，但不会产生任何组件安装步骤。
10. 安装成功后配置锁定；安装失败后不持久锁定。
11. 远程重置必须经过强确认并生成独立任务。
12. 只有远程重置全部成功后才解除安装锁。
13. 重置部分失败或应用中断时保留安全状态和完整日志，支持人工修复后重试。
