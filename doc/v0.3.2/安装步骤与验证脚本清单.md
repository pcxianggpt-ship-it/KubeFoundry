## 2. 盘点结论

- 当前 Java 完整计划最多包含 29 个步骤：28 个 `INSTALL` 步骤和 1 个最终 `VALIDATION` 步骤。
- 28 个 `INSTALL` 步骤已全部绑定同键验证脚本，严格前置/后置验证覆盖率为 100%。
- 验证脚本统一调用 `scripts/lib/verify.sh`，只读取目标节点的 `runtime.env` 白名单变量，不再依赖 `PROJECT_ROOT`、`config.sh` 或嵌套 SSH。
- 验证结果统一为 `0=已满足`、`10=未满足`、`20=验证异常`、`21=验证超时`；未知退出码由执行引擎按验证错误处理，不会触发安装。
- `18-init-k8s-cluster` 前置验证已满足时，执行独立恢复脚本生成本任务所需的控制节点和 Worker Join 产物；日志及证据不记录 Token、证书 Key 或完整 Join 命令。
- `scripts/tests/test_verify_contract.sh` 对步骤映射、普通文件、LF、只读性、非交互、退出码和重复验证一致性执行门禁检查。

## 5. 历史 verify 风险处置

### 5.1 嵌套 SSH

以下当前计划相关脚本原先调用 `ssh_exec_capture` 或直接 SSH，现已迁移为“在当前目标节点执行”：

- `verify-11b-setup-hostname.sh`
- `verify-12-setup-k8s-repo.sh`
- `verify-13-install-k8s-deps.sh`
- `verify-14-replace-kubeadm.sh`
- `verify-15-environment-config.sh`
- `verify-16-install-containerd.sh`
- `verify-17-install-registry.sh`
- `verify-18-init-k8s-cluster.sh`
- `verify-19-modify-cert-expiry.sh`
- `verify-20-add-control-nodes.sh`
- `verify-21-add-worker-nodes.sh`
- `verify-22-install-cni-flannel.sh`

### 5.2 控制端配置依赖

原脚本中的 `PROJECT_ROOT`、`cluster.yaml`、`config.sh` 和控制端公共库依赖均已移除。v0.3.2 统一只读取远端任务目录中的 `runtime.env` 白名单变量和只读验证公共函数。

### 5.3 超时与退出码

- `systemctl`、`kubectl`、`helm`、`curl`、`yum` 和文件系统命令均通过有界命令执行函数调用。
- 验证脚本已统一使用 `0/10/20/21` 契约。
- SSH 不可达、权限不足或 Kubernetes API 不可用均按验证异常处理，不会误判为目标未满足。

### 5.4 敏感信息

- 集群初始化、控制节点加入和 Worker 加入验证不得输出 Join Token、证书 Key、完整 Join 命令或 kubeconfig。
- Redis、MinIO 及其他组件验证不得输出 Secret 内容或带密码的命令。

## 6. 已完成的实施顺序

1. 为 `InstallStep` 增加显式验证脚本、步骤类型和可选产物恢复脚本字段。

4. 迁移其余基础和组件验证脚本，并在计划工厂中启用 100% 严格双重验证。
