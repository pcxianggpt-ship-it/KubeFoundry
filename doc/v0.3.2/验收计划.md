## 2. 验收目标

本计划用于验证 v0.3.2 的九项优化在接口、页面、Java 编排、Bash 脚本、离线介质和真实集群中的行为一致。验收重点是：

1. 失败续跑不会重复执行已满足步骤，也不会在验证异常时误执行安装。
2. YUM 仓库设置 `777` 权限并关闭 firewalld 后正常提供 HTTP 服务。
3. 分组展示不丢失叶子步骤、节点状态和日志。
4. MinIO 参数能够正确应用，且启用 MinIO 后少于 4 个正式工作节点时无法开始安装。
5. etcd 备份作为最后一个单元产生可校验快照。
6. 安装范围确认页逐项显示节点 IP。
7. 安装失败且未安装 Helm 时仍能重置。
8. 重置只清理 KubeFoundry 受管配置，不覆盖用户内容。
9. Redis Sentinel 能在断网环境安装并完成故障切换验证。

## 3. 验收原则

- 自动化测试通过是进入真实环境验收的前置条件，不替代真实集群验收。
- 所有真实环境操作使用隔离测试集群，禁止在生产集群进行故障注入、重置或 Redis 主节点中断。
- 每个用例必须记录执行时间、发布包 SHA-256、集群 ID、任务 ID、操作者、实际结果和脱敏证据位置。
- 涉及失败任务时必须同时保留来源任务 ID 和续跑任务 ID。
- 密码、Token、私钥、Join 命令、Secret、完整 kubeconfig 和未脱敏日志不得进入验收文档或截图。
- 任一阻断级用例失败，v0.3.2 不得发布；非阻断偏差必须有明确风险接受结论。
- 所有验收文档、脚本、YAML 和证据索引使用 LF。

## 4. 验收环境

### 4.1 环境 A：早期失败与无 Helm 重置

用于第二阶段失败和无 Helm 重置，不承担 MinIO Worker 数量边界验收：

| 角色 | 数量 | 说明 |
| --- | --- | --- |
| 管理服务 | 1 | 部署候选 v0.3.2 发布包 |
| 控制节点 | 1 | 主控制节点 |
| 工作节点 | 按重置场景 | 不要求为 MinIO 单独准备 3 Worker 环境 |
| Registry | 1 | 可与独立节点或既有支持拓扑一致 |

环境要求：

- 能在 Helm 安装前人为制造基础步骤失败。
- 节点和管理服务时间同步。

### 4.2 环境 B：完整离线集群

用于完整安装、MinIO、Redis Sentinel、etcd 备份和续跑：

| 角色 | 最低数量 | 说明 |
| --- | --- | --- |
| 管理服务 | 1 | 与目标节点网络可达 |
| 控制节点 | 1 | 可扩展至 3 个控制节点验证高可用 |
| 工作节点 | 4 | 全部为正式 Worker；成功安装用例中应具备正常调度条件 |
| Registry | 1 | 包含全部冻结镜像 |

环境要求：

- 目标节点不能访问互联网，安装只使用发布包和私有 Registry。
- 存储容量满足 OpenEBS、MinIO、Redis 和 etcd 备份测试。
- 能安全执行 Pod 删除、服务停止和安装步骤失败注入。

### 4.3 环境 C：YUM 权限与网络边界

用于 YUM 权限、firewalld 和配置所有权验收：

- 使用项目声明支持的 RHEL 兼容发行版，执行时记录具体版本和内核。
- `/var/www` 父级目录可预设为 httpd 无搜索权限，用于复现 HTTP 403。
- 安装步骤执行后确认 firewalld 已停止并禁用。
- 预置用户自定义 sysctl、limits、hosts 和 containerd 配置，验证重置保护边界。

## 7. 失败续跑与双重验证验收

| 编号 | 场景与操作 | 预期结果 | 级别 |
| --- | --- | --- | --- |
| RES-001 | 正常安装中人为使一个基础步骤失败，任务结束后点击续跑 | 创建新的任务 ID；新任务记录来源任务 ID；原任务状态、步骤和日志不变化 | 阻断 |
| RES-002 | 预先正确安装 Registry，再执行或续跑安装 | Registry 前置验证通过；步骤显示“已验证并跳过”；不上传 Registry 安装介质、不执行安装脚本 | 阻断 |
| RES-003 | 让验证脚本返回“目标未满足” | 执行安装脚本，随后执行后置验证；验证通过后步骤成功 | 阻断 |
| RES-004 | 模拟 SSH、权限或 Kubernetes API 异常，使前置验证返回异常 | 步骤失败并标记 `PREVERIFY_ERROR` 或超时；不得执行安装脚本 | 阻断 |
| RES-005 | 安装脚本退出 0，但后置验证未通过 | 步骤以 `POSTVERIFY_FAILED` 失败，不能标记成功 | 阻断 |
| RES-006 | 集群初始化已完成但原任务失败，发起续跑 | 初始化步骤验证跳过；当前续跑任务安全恢复 Join 产物；后续节点可加入；日志不出现 Token | 阻断 |
| RES-007 | 多节点步骤中部分节点已满足、部分未满足 | 已满足节点跳过，其他节点执行；步骤按规则汇总且逐节点结果准确 | 重要 |
| RES-008 | 对成功任务、跨集群任务、无完整快照历史任务和活动任务发起续跑 | 返回稳定 4xx 错误，不创建空任务或修改来源任务 | 阻断 |

证据要求：来源/续跑任务响应、步骤与节点状态快照、资源上传审计摘要、脱敏日志和数据库/API 契约结果。

## 10. MinIO 配置与 Worker 门禁验收

### 10.1 节点数量门禁

| 编号 | 场景与操作 | 预期结果 | 级别 |
| --- | --- | --- | --- |
| MINIO-001 | 使用集群配置数据构造 0、1、2、3 个正式 Worker，启用 MinIO 并保存参数 | 配置允许保存，不因 Worker 数量在编辑阶段被阻止 | 重要 |
| MINIO-002 | 集群配置中有 3 个正式 Worker，启用 MinIO 后开始安装 | 安装开始即返回 `409 MINIO_WORKER_COUNT_INSUFFICIENT`；`required_workers=4`、`actual_workers=3`；不创建执行任务、不运行任何步骤 | 阻断 |
| MINIO-003 | 将同一集群配置调整为恰好 4 个正式 Worker 后开始安装 | 其他配置合法时通过准入并进入安装 | 阻断 |
| MINIO-004 | 集群配置包含 4 个正式 Worker，但只有 3 个 Ready，开始安装 | 不得因 Ready Worker 数量专项门禁提前拒绝；后续由 Tenant、Pod 和 PVC 通用就绪验证决定安装结果 | 重要 |
| MINIO-005 | MinIO 已启用后将集群配置中的正式 Worker 减少到 3 个 | 配置不被静默关闭或清空；下次安装或组件补装在开始时拒绝继续 | 重要 |

Worker 计数规则：只统计 `is_draft=false` 且角色包含 `worker` 的当前集群节点；纯控制节点和纯 Registry 节点不计数。

## 20. 通过标准

- 所有阻断级用例通过。
- 重要级用例没有未评审的失败；允许延期的项目有负责人、目标版本和风险接受记录。
- Java、Vue、Bash、Flyway、LF、敏感信息和发布包测试全部通过。
- 环境 B 完成全量离线安装、故障续跑、重置和再次安装。
- MinIO 配置保存不校验 Worker 数量；安装开始时，0～3 个正式 Worker 无法通过准入，恰好 4 个正式 Worker 时可进入安装；验收中不得出现 Ready Worker 数量专项门禁，也无需分别搭建 3 Worker 和 4 Worker 环境。
- Redis Sentinel 完成最小读写和受控故障切换。
- etcd 产生至少一个通过完整性检查的快照，且备份单元为安装计划最后一项。
- 最终验收结果记录到 `doc/v0.3.2/最终验收清单.md`，并由非实现者至少复核一次高风险用例证据。

## 21. 未通过处理

- 阻断级用例失败：停止发布，记录问题、复现步骤、影响范围和修复版本；修复后重新执行受影响用例及相关回归。
- 环境或介质阻塞：记录阻塞原因，不得标记为通过；环境恢复后继续执行。
- 验收过程中发现设计与实现不一致：先更新设计、接口和开发计划并完成评审，再修改实现。
- 发现敏感信息泄露、越界删除、验证异常触发安装或不可恢复的 etcd 备份时，立即停止后续验收并按最高优先级处理。
