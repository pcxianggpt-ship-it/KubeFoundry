# 续跑快照校验与进度页优化

## 问题与修复

用户反馈点击“从失败处续跑”返回 `RESUME_SNAPSHOT_MISMATCH`，提示“安装路径或运行参数已变化”；同时要求入口移到页面上端，左侧步骤栏增加滚动条。

已在本地后端集成测试复现相同错误：启用存储与日志组件时，创建安装快照会将 MinIO 容量、CPU、内存等参数注入每个节点的运行环境；续跑校验只使用基础运行参数，因此配置未变也被判定不一致。

续跑校验改为复用 `InstallationSnapshotService.previewPayload` 的完整参数生成逻辑。保持对集群配置、组件配置版本、节点身份及凭据、运行参数和步骤计划的校验；实际参数变化仍拒绝续跑。继续创建新任务并原样复制来源快照，不修改来源任务或快照。

“从失败处续跑”移到进度页顶部标题右侧，窄屏自动换行，保留提交中禁用和防重复提交行为。左侧步骤列表增加受视口高度约束的独立纵向滚动区域，支持键盘聚焦及滚动；底部返回入口保留在滚动区域外。

## 断点续跑与全量重跑（2026-10-06）

当前版本继续为 v0.3.2。本次读取玫瑰园服务器任务记录确认：任务 #5 的第 25 步 MinIO 失败，第 26、27 步因组件依赖跳过，前面基础步骤及后面监控、Redis、etcd 备份步骤已成功。点击旧入口产生来源为 #5 的续跑任务 #6，但新任务从第一个步骤重新前置验证，第 16 步集群健康检查因 MinIO Pending 失败，实际没有到达第 25 步。

源码根因是 `InstallResumeService` 重建完整计划后，对所有步骤节点仍生成 `RemoteStepRunner.run` 操作，`JobService` 没有来源完成状态的复用逻辑。旧行为会重新检查全部步骤，满足前置验证时跳过安装脚本，不能等同于真正的断点续跑。

页面顶部拆成“断点续跑”和“全量重跑”：

- 断点续跑使用 `/resume`，按稳定步骤键和节点 ID 复用来源成功、前置验证满足或既有断点复用的结果，显示“已完成并复用”；只执行失败、未完成和因依赖跳过且无历史完成记录的节点。
- 多次续跑向上追溯同一快照及同一完整计划的来源链。最近一次实际失败会阻断更早的成功；全量重跑形成新的执行基线，不继承它之前的完成结果。
- 只为本次实际待执行的消费者恢复必要产物。节点仍需加入集群时，由原初始化步骤的前置验证及 `18-recover-k8s-keys.sh` 恢复当前任务的加入产物并刷新 token；不能直接复制可能过期的加入凭据。MinIO 续跑不需要加入产物，不因此重新运行已完成的初始化步骤。
- 全量重跑使用独立 `/rerun` 接口，响应 `run_mode=rerun`，从第一步重新检查完整计划。保留正常前置验证的安全跳过行为，不执行重置或强制清理。
- 两种模式均创建新任务、保留来源记录，并保留快照校验及活动任务互斥。请求进行期间同时禁用两个按钮，来源提示和任务列表分别展示两种运行模式。

浏览器验证使用隔离模拟接口，没有点击玫瑰园服务器的续跑或重跑按钮。分别点击两个按钮，确认实际 POST 路径为 `/resume`、`/rerun`，新任务跳转及模式显示正确。Apple 主题在 320、768、1024、1440 宽度均无整页横向溢出；经典主题 320 宽度也正常；键盘 Tab 可从断点续跑移动到全量重跑并显示焦点。

前端 20 个测试文件、105 项测试全部通过，覆盖按钮互斥、防重复提交、两种接口和任务来源展示、失败时留在来源页、断点复用状态展示。生产构建通过，仅有既存依赖注释与较大输出文件提示。

后端完整回归共 42 个测试类、260 项测试，19 项跳过，失败与错误均为 0。定向验证覆盖逐节点复用、连续续跑追溯、最新失败阻断旧成功、全量重跑实际执行、加入产物恢复、快照校验及来源记录保持不变。本次安装状态机修改由 Sol 参与实现和专项分析，主模型复核并运行完整验收。

部署此修复后，玫瑰园任务 #6 已实际失败的健康检查仍保留为失败记录。若要从原 MinIO 故障继续，应返回任务 #5 点击“断点续跑”；从 #6 续跑不会用 #5 的旧成功掩盖 #6 的真实失败。
