## 3. 风险控制

- SSH、Join Token、Redis Secret、私钥和完整 kubeconfig 不进入日志、事件、快照或普通接口响应。
- 远端验证异常不会被解释成“尚未安装”，不会触发有副作用的安装脚本。
- 重置先完成受管文件、标记块、基线清单、SHA-256、权限和符号链接预检，再执行破坏性清理。
- Redis 故障切换脚本必须显式设置 `KF_ACCEPT_REDIS_FAILOVER=YES`，只允许在隔离测试集群使用。
- etcd 快照由 Pod 内的 `etcdctl` 写入已挂载的宿主机 etcd 数据目录；宿主机使用同一文件执行 SHA-256、复制后再校验，并在备份目录原子更名和清理临时快照。该镜像没有 `etcdutl`、`sha256sum`、`cat`、`rm` 等命令，因此状态检查使用镜像内的 `etcdctl snapshot status`。systemd 写入白名单仅增加该受管数据目录；重置删除受管 unit 和脚本，但保留快照。

## 4. 评审结论与限制

门禁 A 已由用户确认；测试基线和 Flyway 版本检查已确认。门禁 B～E 已按实现和自动化测试冻结，具体结果记录在开发计划与最终验收清单中。

当前没有独立 Sol 或第二实现者完成高风险专项复核。SSH 执行、安装状态机、配置所有权、破坏性重置、Redis 凭据和 etcd 备份只能记为“实现及自动化通过”，必须在真实集群验收后由非实现者复核证据，才能签署发布通过。
