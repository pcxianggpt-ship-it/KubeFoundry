# KubeFoundry v0.3.2 使用手册

## 1. 操作入口

v0.3.2 只支持 Web Wizard。旧 `scripts/main.sh`、旧 CLI 参数和独立 SSH 登录步骤已停止支持；`scripts/steps/` 与 `scripts/verify/` 是 Java 后端内部实现，不能作为用户接口直接编排。

访问 `http://<管理服务器IP>:10001`，按以下顺序操作：

```text
创建或选择集群
→ 完成集群配置和节点配置
→ 测试全部节点
→ 配置 Kubemate 组件
→ 确认安装范围
→ 开始安装
→ 查看部署单元、叶子步骤、节点状态和日志
```

## 2. 节点与安装范围

- 节点可以组合承担 Registry、控制节点和 Worker 角色。
- 安装确认页显示主机名、IP、角色和免密验证状态；开始前逐项核对目标。
- 草稿节点不进入安装快照，也不计入 MinIO Worker 数量。
- 节点密码只用于首次 SSH 建联并加密保存；后续步骤使用集群密钥，不依赖目标 YUM 源中的 `sshpass`。

## 3. MinIO 参数

在“集群配置 → Kubemate 组件”启用 MinIO 后可设置：

| 参数 | 默认值 |
| --- | --- |
| PVC 容量 | `10Gi` |
| CPU request | `250m` |
| CPU limit | `2` |
| 内存 request | `512Mi` |
| 内存 limit | `4Gi` |

配置保存时允许 Worker 少于 4 个；运行安装预检查和开始完整安装或组件补装时检查正式 Worker 数量。0～3 个时返回 `MINIO_WORKER_COUNT_INSUFFICIENT`，恰好 4 个及以上可进入安装。无需为了验收搭建四个真实 Worker；数量边界由配置数据和预检查验证。系统不增加 Ready Worker 数量专项门禁，实际调度和健康由 Tenant、Pod 和 PVC 通用验证决定。

## 4. 安装进度与分组

安装页先展示部署单元，再展开叶子步骤。NFS exports、NFS Provisioner 和 Worker 挂载统一位于“部署 NFS 组件”；containerd 单独显示；etcd 备份是完整安装计划最后一个维护单元。

执行前验证已经满足的步骤显示“已验证并跳过”。验证异常不会继续安装；安装脚本执行完成后仍须通过执行后验证才会成功。

## 5. 断点续跑与全量重跑

失败、中断或部分成功的 v0.3.2 安装或组件补装任务提供两个按钮：

- 系统创建新任务 ID，并记录来源任务 ID；
- 来源任务、日志、事件和步骤保持只读；
- 新任务复用来源任务的不可变配置快照；
- **断点续跑**：复用来源任务中已完成的步骤及节点，显示“已完成并复用”；执行失败、未完成和因依赖跳过的节点，不再从第一个步骤重新连接和验证。
- **全量重跑**：从第一个步骤重新检查完整计划，仍保留执行前验证；已满足的安装条件会安全跳过，不等同于集群重置。
- 同一步骤有部分节点成功时，断点续跑只执行未完成节点；多次续跑仍保留历史完成记录。
- 后续步骤需要前置产物时会恢复这些产物，例如为尚未加入集群的节点刷新加入凭据。已经完成的加入步骤不会因此重新执行。
- 提交期间两个按钮均禁用，防止重复创建或同时发起不同模式。

历史 v0.3.1 任务、成功任务、跨集群任务、快照不完整任务和存在活动安装类任务时不能通过上述入口创建任务。配置或目标节点变化仍须重新预检，不能绕过来源快照校验。

## 6. 集群重置

重置是破坏性操作，必须核对页面显示的集群、节点 IP、来源任务和清理范围，并完成强确认。第二阶段失败且从未安装 Helm 的任务也可以重置；系统只在存在 Helm 安装或受管 release 证据时生成组件清理步骤。

重置只清理能够证明由 KubeFoundry 管理的独立文件、标记块、基线配置、资源和 release。若检测到用户修改了需要恢复的文件，会报告冲突并停止对应恢复，不覆盖用户内容。etcd 受管 service、timer 和脚本会被移除，但 `/var/backups/kubefoundry/etcd` 中的快照保留。

## 7. Redis Sentinel 与 etcd

Redis 使用冻结的 Bitnami Chart 和私有 Registry 安装，持久化使用 `localpath`，也可通过 `KF_REDIS_STORAGE_CLASS` 显式指定。日常查看只使用组件和步骤状态；删除 Redis master Pod 的故障切换脚本仅供隔离验收环境使用。

在“集群配置 → Kubemate 组件”启用 Redis 哨兵模式后，可填写“Redis / Sentinel 密码”。Redis 与 Sentinel 使用同一密码，支持特殊字符和中文；不能仅包含空白、包含控制字符或超过 256 个字符。密码加密保存，页面仅显示“已配置”，再次保存时留空保持原密码；从未配置时留空则在安装时生成随机密码。

部署时将配置密码写入 `redis-sentinel/redis-auth` Secret 的 `redis-password` 字段，Chart 引用该 Secret；密码不进入任务快照、运行参数或日志。临时文件限制为仅所有者可读写，完成验证或安装后清理。已有 Secret 密码与配置不一致时会报错，不自动覆盖；已安装或正在安装的组件不可在线改密。备份与迁移 KubeFoundry 数据时必须一并保留原凭据主密钥。

完整安装最后会安装 etcd systemd timer，并立即生成一个经过完整性和 SHA-256 检查的快照。默认目录为 `/var/backups/kubefoundry/etcd`，每日 `02:10` 执行并保留 7 份。

## 8. 故障排查

- “执行前验证失败”：检查对应节点日志中的稳定原因码，确认是目标未满足还是验证异常。
- `MINIO_WORKER_COUNT_INSUFFICIENT`：在集群配置中增加正式 Worker；不需要伪造 Ready 状态。
- 配置所有权冲突：检查报错路径，不要手工删除基线清单或强制覆盖用户配置。
- 组件离线介质缺失：补齐部署目录的 `kube-media/` 后创建续跑任务，不能通过联网下载绕过。
- 任务日志不得复制传播密码、Token、私钥、Secret、Join 命令或完整 kubeconfig。
