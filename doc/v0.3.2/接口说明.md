# KubeFoundry v0.3.2 接口说明

## 1. 兼容范围

v0.3.2 继续使用现有 Web API，并新增续跑血缘、部署单元元数据和 MinIO 资源参数。旧任务仍可查看，但只有具有完整 v0.3.2 安装快照和稳定步骤键的失败、中断或部分成功任务可以续跑。旧 Bash CLI 已停止支持。

## 2. 安装任务断点续跑与全量重跑

```http
POST /api/clusters/{clusterId}/jobs/{jobId}/resume
POST /api/clusters/{clusterId}/jobs/{jobId}/rerun
```

`resume` 对应“断点续跑”：按稳定步骤键及节点 ID 复用来源任务已成功或已验证跳过的执行记录，仅执行失败、未完成及因依赖跳过的节点。连续续跑时可沿来源链查找未执行节点的最近执行记录；最新实际失败不能被更早的成功覆盖。

`rerun` 对应“全量重跑”：不复用完成断点，从第一个步骤重新执行完整计划。仍保留已有执行前验证，已满足的安装条件可安全跳过安装脚本，不执行集群重置或强制删除。

若待执行节点需要尚未恢复的前置产物，续跑会保留相应产物恢复流程。例如加入集群的节点需要通过原初始化步骤的前置验证及恢复脚本刷新加入凭据；所有加入节点已完成时，不要求旧加入产物存在，也不重新执行初始化步骤。

成功返回 `202 Accepted`：

```json
{
  "job_id": 126,
  "status": "pending",
  "source_job_id": 123,
  "run_mode": "resume"
}
```

两种入口均返回 `202 Accepted` 并创建新任务，不修改来源任务。全量重跑响应中的 `run_mode` 为 `rerun`，其他字段结构相同：

| 字段 | 说明 |
| --- | --- |
| `source_job_id` | 来源任务 ID；普通任务为空 |
| `run_mode` | `normal`（普通安装）、`resume`（断点续跑）或 `rerun`（全量重跑） |

步骤继续使用既有终态；执行前验证通过时为 `status=skipped`、`status_reason=PREVERIFY_SATISFIED`。验证异常和执行后验证失败分别通过稳定原因码及脱敏消息呈现。

断点复用的节点返回 `status=skipped`、`message=RESUME_SOURCE_SUCCEEDED`；整步所有节点均复用时，步骤返回相同的 `status_reason`，页面显示“已完成并复用”。来源快照、目标节点、配置和完整计划校验及活动任务互斥对两种入口均生效。

常见续跑错误返回 `409`，错误码以 `RESUME_` 开头；跨集群查询返回 `404 CLUSTER_JOB_NOT_FOUND`。同一集群已有活动安装类任务时返回 `409 INSTALLER_JOB_ACTIVE`。

## 3. 部署单元元数据

安装步骤响应和不可变安装快照保存稳定步骤键、部署单元键、部署单元名称、顺序和类型。前端依据持久化元数据分组，不根据中文步骤名称猜测。NFS exports、NFS Provisioner 和 Worker 挂载统一归入“部署 NFS 组件”；containerd 使用独立部署单元；`etcd_backup` 为完整安装计划最后一个 `MAINTENANCE` 单元。

## 4. MinIO 组件配置

```http
GET /api/clusters/{clusterId}/components
PUT /api/clusters/{clusterId}/components
```

MinIO 配置字段：

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `minio_pvc_size` | `10Gi` | 正 Kubernetes 存储 Quantity |
| `minio_cpu_request` | `250m` | 正 CPU Quantity |
| `minio_cpu_limit` | `2` | 不小于 request |
| `minio_memory_request` | `512Mi` | 正内存 Quantity |
| `minio_memory_limit` | `4Gi` | 不小于 request |

配置保存阶段不校验 Worker 数量。运行安装预检查、开始完整安装或组件补装时，若启用了 MinIO，则统计当前集群 `is_draft=false` 且角色包含 `worker` 的节点；少于 4 个时返回：

```json
{
  "code": "MINIO_WORKER_COUNT_INSUFFICIENT",
  "message": "启用 MinIO 至少需要 4 个工作节点，当前为 3 个",
  "details": {
    "required_workers": 4,
    "actual_workers": 3
  }
}
```

HTTP 状态为 `409 Conflict`。该准入不检查 Worker 的 Ready 状态。

## 5. Redis 哨兵密码配置

沿用 `GET/PUT /api/clusters/{clusterId}/components`，组件组键为 `redis_sentinel`：

```json
{
  "groups": [{
    "key": "redis_sentinel",
    "enabled": true,
    "config": { "password": "<安装时使用的密码>" }
  }]
}
```

- `password` 仅写入，不在 GET 或 PUT 响应返回；首次启用 Redis 时必填，支持非控制字符，最多 256 个字符，不能为空或仅为空白。
- 响应 `config` 仅含 `has_password` 布尔值。该字段是展示状态，不可用于设置、清除或伪造密码。
- 已保存凭据且不修改密码时，省略 `password` 字段以保留原值；显式传入空字符串时返回 `400 COMPONENT_CONFIG_INVALID`。首次启用时缺少 `password` 也会被拒绝，伪造 `has_password=true` 无效。
- Redis 未启用时无需配置密码；预检查、完整安装和 Redis 补装均会拦截“已启用但没有保存密码”的旧配置。部署必须提供非空密码文件，不再生成随机密码。
- 数据库中使用现有 AES-GCM 凭据主密钥加密，不新增明文字段。安装快照排除整个 Redis 密码配置；配置版本仍参与续跑一致性校验。
- 改变密码会使组件预检查过期，并禁止沿用旧配置任务的续跑。已安装或正在安装的组件改变密码返回 `409 COMPONENT_GROUP_READ_ONLY`。
- 密码只通过独立临时文件上传，执行前后验证均核对 Secret。已有 Secret 密码不一致时失败，不执行在线密码轮换。

## 6. 重置兼容策略

重置允许来源安装任务为成功、失败或中断，但仍要求不可变快照、破坏性确认且集群不存在活动任务。只有来源任务存在 Helm 安装成功或受管 release 证据时才创建相应组件清理步骤。系统配置按稳定头标记、成对标记块或基线 SHA-256 恢复；发现用户后续修改时安全失败，不覆盖用户内容。

## 7. 安全约束

API、任务事件、日志和安装快照不得返回 Redis 密码、Kubernetes Secret、Join Token、私钥或完整 kubeconfig。所有错误消息只携带稳定错误码和不含凭据的诊断信息。
