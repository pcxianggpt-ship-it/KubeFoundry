# NFS 服务器位置与角色分配

## 配置与保存

2026-10-05，Kubemate 组件配置中的 NFS 服务器改为“集群内部”和“集群外部”两个选项。

| 位置 | 地址输入 | 保存后的角色 |
| --- | --- | --- |
| 集群内部 | 从当前集群已保存、非草稿的节点中选择，显示节点名称与 IP，支持搜索 | 对选中节点附加“NFS 服务器”，保留控制节点、工作节点、镜像仓库等基础角色 |
| 集群外部 | 输入有效 IPv4 地址 | 移除所有集群节点的 NFS 服务器标签，即使输入 IP 与某集群节点相同也不分配角色 |

内部服务器更换节点时，角色同步转移；禁用 NFS 后角色移除。切换位置会清空旧服务器地址，避免把外部 IP 当作内部选择，或误保留旧节点。未完成配置就禁用 NFS 时，可以保存，未完成的配置清空；完整的禁用配置保留供再次启用。

内部没有可选节点时提示先添加并保存节点；节点列表加载失败时提供重试，内部配置暂不能保存，外部仍可输入 IP。启用 NFS 时继续校验共享目录、Worker 挂载目录及 StorageClass 名称。已安装、安装中的组件保持只读，活跃安装任务仍拦截配置写入。

## 数据与执行逻辑

2026-10-05 表单调整：NFS 服务器位置独占一行。新配置的共享目录、Worker 挂载目录默认填入当前集群 Kubernetes 工作目录下的 `nfs_root`，例如工作目录为 `/data/k8s_install` 时，两者均为 `/data/k8s_install/nfs_root`；StorageClass 默认填入 `nfs-storage`。已保存的自定义路径和名称保留，工作目录末尾的斜杠不会产生双斜杠。工作目录由集群工作区传给组件表单，无需额外请求接口。

- 复用原 NFS 配置字段：内部对应 `exports_mode: managed`，外部对应 `exports_mode: external`，`server_address` 保存所选节点 IPv4 或外部 IPv4，无新增数据库字段或迁移。
- 保存启用的内部配置时，后端验证服务器地址属于当前集群的非草稿节点，拒绝其他集群节点、草稿节点及未知地址。
- 节点列表接口根据已保存、已启用的内部 NFS 配置，在 `roles` 中附加 `nfs_server`。配置页和安装进度页共用该角色结果与“NFS 服务器”图标标签。
- `nfs_server` 是组件配置派生角色，不写入手工编辑的基础 `node_roles`。编辑节点时不回写该角色，复制出的草稿节点也不会继承 NFS 分配。组件保存失败不会改变原有分配。
- 沿用 `NfsTargetResolver` 按配置地址选择实际执行节点的逻辑；安装时仍要求内部节点测试成功，外部模式不在集群节点部署受管 exports。本次配置保存不执行 SSH、安装或系统授权操作。
- 改动使用原组件保存事务；只影响组件配置版本与组件预检查，不因派生角色增加节点配置版本。
