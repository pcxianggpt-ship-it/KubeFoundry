# 节点登录配置合并与固定离线安装设计

## 1. 目标

本次优化调整 Web Wizard 的节点登录配置和集群安装模式：

1. 将 SSH 登录配置合并到节点配置。
2. 每个节点使用 `root` 用户、固定 SSH 端口 `22`，且必须配置登录密码。
3. 后端为每个集群生成独立 SSH 密钥，通过密码首次登录并写入公钥，后续安装统一使用私钥。
4. 节点密码加密保存到 SQLite，不通过 API、日志或任务产物泄漏。
5. 支持选择一个或多个节点并完整复制为草稿。
6. 删除安装模式选择，集群固定使用离线安装。
7. 删除用户填写的操作系统和架构字段，通过“测试全部节点”自动识别并保存。

## 2. 页面流程

Web 向导调整为八个步骤：

```text
1. 集群基础配置
2. 节点与登录配置
3. 路径和安装介质
4. 生态组件
5. 环境预检查
6. 配置确认
7. 安装执行
8. 安装结果
```

### 2.1 集群基础配置

- 删除安装模式选择控件。
- 显示只读提示“当前版本仅支持离线安装”。
- 前端创建和更新集群时不再提交 `install_mode`。
- 后端不再读取、保存或返回 `install_mode`。

数据库迁移删除 `clusters.install_mode` 字段；离线安装成为系统唯一行为，不再作为集群配置持久化。

### 2.2 节点与登录配置

删除独立的“SSH 配置”步骤。节点表格保持紧凑，显示：

```text
选择框
主机名
IP
IPv6
角色
密码状态
草稿状态
操作系统
系统版本
架构
测试状态
测试时间
操作
```

新增或编辑节点时使用弹窗，字段包括：

```text
主机名
IPv4
IPv6
角色
登录密码
```

固定规则：

- SSH 用户固定为 `root`。
- SSH 端口固定为 `22`。
- 页面不显示默认用户、SSH 端口和私钥路径。
- 页面不提供操作系统和架构输入项。
- 新增正式节点时密码必填。
- 编辑已有且已配置密码的节点时，密码框留空表示保留原密码。
- 输入新密码表示覆盖原密码。
- API 响应只返回 `has_password`，不返回密码明文或密文。
- API 忽略或拒绝请求中的 `os_type`、`os_version` 和 `arch`，这些字段只能由节点测试或正式预检查更新。

节点表格只读展示最近一次测试识别出的操作系统发行版、版本和架构。未测试或测试结果已失效时显示“待测试”。

## 3. 节点复制与草稿

节点列表支持多选和“复制所选”操作。

### 3.1 复制行为

- 可同时复制一个或多个节点。
- 副本完整保留原节点的主机名、IP、IPv6、角色和登录密码。
- 副本可保留原节点最近识别出的操作系统和架构作为只读参考，但测试状态统一设为 `stale`，不得继承原节点的测试成功状态。
- 密码复制在后端数据库内完成，前端不会读取密码。
- 每个副本创建后标记为草稿。
- 副本可暂时与原节点具有相同主机名和 IP。

### 3.2 草稿规则

草稿节点允许：

- 缺少主机名、IP或密码。
- 与其他节点暂时具有重复的主机名或 IP。
- 保存在数据库中并在后续继续编辑。

草稿转为正式节点需要同时满足：

1. 主机名非空。
2. IPv4 非空且格式正确。
3. 已配置登录密码。
4. 主机名在集群内唯一。
5. IPv4 在集群内唯一。
6. 其他已有节点校验规则全部通过。

编辑保存后，如果节点满足全部条件，后端自动将 `is_draft` 设为 false；否则继续保留草稿状态，并返回可展示的校验问题。

存在以下任一情况时，禁止启动预检查或安装：

- 存在草稿节点。
- 正式节点缺少密码。
- 正式节点主机名或 IP 重复。
- 节点必填字段或格式校验失败。

错误响应必须列出节点 ID、主机名和具体问题，便于页面定位。

## 4. 数据模型

### 4.1 nodes 表

新增字段：

```text
login_password_encrypted TEXT NOT NULL DEFAULT ''
is_draft INTEGER NOT NULL DEFAULT 0
os_type TEXT NOT NULL DEFAULT ''
os_version TEXT NOT NULL DEFAULT ''
arch TEXT NOT NULL DEFAULT ''
node_test_status TEXT NOT NULL DEFAULT 'pending'
node_tested_at TEXT
node_test_message TEXT NOT NULL DEFAULT ''
node_test_config_version INTEGER
```

现有字段 `ssh_user` 和 `ssh_port` 暂时保留用于数据库兼容，但后端上下文和执行器固定使用：

```text
ssh_user = root
ssh_port = 22
```

API 不再接受用户自定义的 `ssh_user` 和 `ssh_port`。

`os_type`、`os_version` 和 `arch` 由节点测试及正式预检查写入，API 不接受用户手工设置。架构统一转换为项目内部值：

```text
x86_64  -> amd64
aarch64 -> arm64
```

其他架构保留标准化后的原始值，并由支持范围校验决定是否允许安装。

### 4.2 clusters 表

删除 `install_mode` 字段。安装模式不再属于集群配置，系统固定执行离线安装流程。

迁移需要从 `clusters` 表移除该字段，并确保集群创建、更新和详情接口均不再依赖该字段。若迁移前存在非离线安装历史数据，不再转换字段值，统一按当前版本的离线安装语义执行后续任务。

### 4.3 集群 SSH 密钥

每个集群拥有独立密钥对，并记录后端管理的私钥路径。建议路径：

```text
data/credentials/clusters/{cluster_id}/id_rsa
data/credentials/clusters/{cluster_id}/id_rsa.pub
```

目录和文件权限：

```text
credentials 目录：0700
集群密钥目录：0700
私钥：0600
公钥：0644
```

现有 `ssh_credentials` 表在迁移期继续保留，用于记录集群密钥路径；认证类型固定为 `key`，用户固定为 `root`。页面不再直接维护该表。

## 5. 密码加密

后端首次启动时创建主加密密钥文件，建议路径：

```text
data/credentials/master.key
```

要求：

- 使用密码学安全的随机源生成。
- 文件权限为 `0600`，父目录权限为 `0700`。
- 后端启动时校验权限；权限过宽时拒绝处理节点密码并输出明确错误。
- 使用纯 Python 的 `KF1.` 版本化认证加密格式保存节点密码，避免离线包依赖平台相关二进制扩展。
- 主密钥文件必须长期保留；丢失后旧密码不可恢复。
- 主密钥和节点密码不得写入 Git。

密码只允许出现在：

```text
HTTPS 请求体或受信任本地请求体
后端进程内存
加密后的 SQLite 字段
sshpass 的 SSHPASS 环境变量
```

密码不得出现在：

```text
命令行参数
API 响应
应用日志
节点日志
任务事件
异常消息
cluster.yaml
config_snapshot.json
runtime.env
进程调试输出
```

### 4.4 集群测试状态

`clusters` 增加配置版本和最近测试状态字段：

```text
node_config_version INTEGER NOT NULL DEFAULT 1
node_test_status TEXT NOT NULL DEFAULT 'pending'
node_tested_at TEXT
node_test_job_id INTEGER
```

新增、复制、编辑或删除节点时递增 `node_config_version`，并立即将集群测试状态设为 `stale`。修改主机名、IP、IPv6、角色或密码均视为关键配置变化。

测试任务启动时保存当前 `node_config_version`。只有任务成功且任务版本仍等于集群当前版本时，测试结果才有效，避免测试执行期间配置变化导致旧结果覆盖新配置。

## 6. 节点测试与 SSH 密钥初始化

节点配置页面提供唯一的“测试全部节点”按钮。测试使用任务系统创建异步 `node_test` 任务，通过 SSE 展示进度、节点状态和日志。

节点测试按以下顺序执行：

```text
校验节点和草稿状态
  -> 创建 node_test 任务并记录 node_config_version
  -> 为集群创建或复用独立 SSH 密钥
  -> 检查 sshpass 和 ssh-keygen
  -> 解密每个节点的登录密码
  -> 并行使用 sshpass -e 测试全部节点
  -> 创建 /root/.ssh 并设置权限
  -> 幂等写入 authorized_keys
  -> 验证私钥免密登录
  -> 读取 /etc/os-release 和 uname -m
  -> 回写节点操作系统、版本、架构和测试结果
  -> 校验集群操作系统与架构同构
  -> 汇总并保存任务结果
```

具体要求：

- 存在草稿、缺少密码、主机名或 IP 重复时，不创建测试任务。
- 全部节点并行测试，不因单节点失败而提前停止。
- 使用 `sshpass -e` 和 `SSHPASS` 环境变量，不将密码拼入命令行。
- 首次连接需要明确处理主机指纹，沿用当前项目的 SSH 主机密钥策略。
- 写入公钥时先检查是否已存在，避免重复追加。
- `/root/.ssh` 权限设为 `0700`，`authorized_keys` 权限设为 `0600`。
- 密钥生成和分发支持重复执行。
- 后续预检查、SCP 和安装任务只使用集群私钥。
- 操作系统从 `/etc/os-release` 读取发行版标识、名称和版本；文件不可读时测试失败。
- 架构通过 `uname -m` 获取并标准化。
- 所有节点必须具有相同架构、相同操作系统发行版和相同主版本。
- 任一节点失败或同构性校验失败时，整个 `node_test` 任务失败。
- 测试成功后保存最近测试时间，并将集群测试状态设为 `success`。
- 测试失败时保存每个节点的成功或失败结果，并将集群测试状态设为 `failed`。

某个节点初始化失败时：

- 对应节点步骤标记为 failed。
- 记录不包含密码的错误摘要和完整 SSH 输出。
- `node_test` 任务最终标记为 failed。
- 其他节点可以继续执行初始化，以便一次发现全部失败节点。
- 系统信息识别仅对密钥验证成功的节点执行。

正式预检查仍重新检测 SSH 连通性、操作系统和架构，防止服务器环境在节点测试后变化。重新检测结果回写节点记录；如果发现操作系统、主版本或架构发生变化，预检查失败，集群测试状态改为 `stale`。

## 7. API 调整

### 7.1 创建节点

```text
POST /api/clusters/{cluster_id}/nodes
```

请求示例：

```json
{
  "hostname": "k8sw1",
  "ip": "192.168.123.131",
  "ipv6": "",
  "role": "worker",
  "password": "secret"
}
```

响应不包含密码：

```json
{
  "id": 2,
  "hostname": "k8sw1",
  "ip": "192.168.123.131",
  "ipv6": "",
  "role": "worker",
  "has_password": true,
  "is_draft": false
}
```

### 7.2 更新节点

```text
PUT /api/nodes/{node_id}
```

- 请求不含 `password` 时保留原密码。
- `password` 为非空字符串时替换密码。
- 不允许通过该接口读取或清空密码。
- 更新后重新计算草稿状态。

### 7.3 复制节点

```text
POST /api/clusters/{cluster_id}/nodes/copy
```

请求：

```json
{
  "node_ids": [2, 3]
}
```

后端要求：

- 所有节点必须属于当前集群。
- `node_ids` 不能为空且不能重复。
- 在同一数据库事务中创建全部副本。
- 副本密码密文由后端直接复制。
- 副本统一设置 `is_draft = true`。
- 任一节点无效时不创建任何副本。

### 7.4 集群和 SSH 接口

- 集群创建、更新接口忽略外部传入的 `install_mode`，不保存安装模式字段。
- 集群详情响应不返回 `install_mode`。
- 独立 SSH 凭据写入接口停止供前端使用；可在兼容期保留，但必须拒绝密码认证和自定义私钥路径。
- 集群详情响应不再需要提供可编辑的 SSH 配置，只返回密钥初始化状态。

### 7.5 测试全部节点

```text
POST /api/clusters/{cluster_id}/node-test
```

请求体为空。接口校验节点配置后创建 `node_test` 异步任务，返回：

```json
{
  "job_id": 18,
  "status": "pending"
}
```

任务沿用现有查询和 SSE 接口：

```text
GET /api/jobs/{job_id}
GET /api/jobs/{job_id}/steps
GET /api/jobs/{job_id}/events
GET /api/job-step-nodes/{item_id}/log
```

同一集群已有 `pending` 或 `running` 的 `node_test` 时返回 `409` 和现有任务 ID。测试期间禁止启动预检查和安装。

`jobs.job_type` 增加 `node_test` 枚举值。节点测试沿用 `job_steps`、`job_step_nodes` 和 `job_events` 保存任务、节点和事件状态，不引入另一套任务模型。

节点列表响应增加以下只读字段：

```text
os_type
os_version
arch
node_test_status
node_tested_at
node_test_message
```

## 8. 前端行为

### 8.1 节点表格

- 增加多选列。
- 增加“复制所选”按钮。
- 未选中节点时禁用复制按钮。
- 密码状态显示“已配置”或“未配置”，不显示任何密码内容。
- 草稿节点使用明显标签，并提供直接编辑入口。
- 操作系统、版本和架构为只读列。
- 页面顶部提供唯一的“测试全部节点”按钮，不提供单节点或勾选测试。
- 测试进行中显示总体进度，并允许查看每个节点的状态和日志。
- 测试结束后展示成功数、失败数和同构性检查结果。

### 8.2 表单校验

新增节点：

- 主机名、IPv4、角色、密码必填。
- 主机名和 IPv4 在集群内唯一。

编辑正式节点：

- 密码可留空，表示保留。
- 其他字段必须满足正式节点规则。

编辑草稿节点：

- 允许保存不完整内容。
- 页面展示未完成原因。
- 全部校验通过后自动变为正式节点。

新增、复制、删除节点，或修改节点主机名、IP、IPv6、角色、密码后：

- 当前测试结果立即显示为“已失效”。
- 预检查和安装按钮立即禁用。
- 用户必须重新执行“测试全部节点”。

### 8.3 任务入口

预检查和安装按钮在存在配置问题时禁用，并显示：

```text
存在 N 个未完成草稿
节点 k8sw2 缺少登录密码
节点 k8sw3 与 k8sw1 的 IP 重复
节点配置已修改，请重新执行“测试全部节点”
最近一次节点测试失败
```

前端禁用只用于改善体验，后端必须执行相同校验，不能依赖前端保证安全。

只有以下条件全部满足时才允许启动预检查或安装：

1. 不存在草稿或节点配置错误。
2. 最近一次 `node_test` 状态为 `success`。
3. 测试任务记录的配置版本等于当前 `node_config_version`。
4. 没有正在运行的节点测试、预检查或安装任务。

## 9. 兼容与迁移

数据库初始化时执行幂等迁移：

1. 为 `nodes` 增加密码密文和草稿字段。
2. 为节点增加系统信息和最近测试结果字段。
3. 为集群增加节点配置版本和最近测试状态字段。
4. 从 `clusters` 表删除 `install_mode` 字段。
5. 现有节点没有密码，保留为正式节点但 `has_password = false`。
6. 现有集群测试状态初始化为 `pending`，必须补录密码并完成节点测试。
7. 现有集群私钥路径可继续使用；若不存在，则在下一次节点测试时生成集群专属密钥。

历史任务、日志和验收数据保持只读，不修改历史快照。

## 10. 错误处理

需要提供明确错误的场景：

- 主加密密钥不存在且无法创建。
- 主加密密钥或密钥目录权限不安全。
- 密码解密失败。
- 管理节点缺少 `sshpass` 或 `ssh-keygen`。
- 节点密码错误。
- SSH 主机不可达。
- 公钥目录或文件权限设置失败。
- 公钥写入失败。
- 私钥免密验证失败。
- `/etc/os-release` 无法读取或字段无法解析。
- 节点架构不受支持。
- 集群内节点架构不一致。
- 集群内节点操作系统发行版或主版本不一致。
- 节点复制请求包含无效或跨集群节点。
- 草稿或重复节点阻止任务启动。
- 节点测试结果不存在、失败或已失效。

所有错误输出必须经过敏感信息过滤。

## 11. 测试与验收

### 11.1 后端测试

- 密码写入 SQLite 后不是明文。
- 重启后可使用主密钥解密密码。
- API 创建、更新、查询节点均不返回密码。
- 日志、事件、快照和 YAML 不包含测试密码。
- 每个集群生成不同密钥。
- 密钥文件和目录权限正确。
- `sshpass` 使用环境变量传递密码。
- 公钥分发幂等。
- 密码错误和工具缺失可定位到具体节点。
- 节点复制完整保留密码能力并标记草稿。
- 批量复制具备事务性。
- 草稿和重复配置阻止预检查及安装。
- 集群 API 和数据库均不再包含 `install_mode`。
- 安装流程固定执行离线安装。
- `node_test` 并行测试全部节点并保存节点级结果。
- 操作系统发行版、主版本和架构能够正确识别并回写。
- `x86_64` 和 `aarch64` 正确标准化。
- 混合架构或混合操作系统发行版/主版本导致测试失败。
- 节点关键配置变化使测试结果立即失效。
- 过期测试任务不能覆盖新配置对应的状态。
- 没有有效成功测试时，预检查和安装 API 拒绝请求。
- 正式预检查检测到系统信息变化时失败并使测试状态失效。

### 11.2 前端测试

- 页面不存在安装模式选择。
- 页面不存在独立 SSH 配置步骤。
- 页面不存在 SSH 用户、端口和私钥路径输入框。
- 页面不存在操作系统和架构输入框。
- 新增节点要求密码。
- 编辑已有节点时空密码保留原密码。
- 支持多选并复制节点。
- 复制结果显示为草稿。
- 草稿问题可见，且阻止预检查和安装。
- 正式节点只显示密码状态。
- 页面只提供一个“测试全部节点”按钮。
- 节点列表只读展示操作系统、版本、架构、测试状态和测试时间。
- 节点测试显示异步进度、汇总结果和节点日志。
- 修改节点关键配置后测试结果显示为失效。
- 没有有效成功测试时，预检查和安装按钮禁用。

### 11.3 集成验收

在至少一个控制节点和两个工作节点上验证：

1. 使用 root 密码录入三个节点。
2. 执行“测试全部节点”，自动生成集群密钥并完成公钥分发。
3. 测试结果正确识别并保存三台节点的操作系统、主版本和架构。
4. 后续 SSH/SCP 全部使用私钥成功。
5. 重启后端后测试结果仍可查看，且无需重新输入密码。
6. 复制节点、编辑草稿并转为正式节点。
7. 节点配置变化后旧测试结果失效，必须重新测试。
8. 存在未完成草稿或测试失败时不能启动预检查或安装。
9. 使用错误密码时页面可定位失败节点，日志不包含密码。
10. 使用混合架构或不同操作系统发行版/主版本时测试失败。
11. 完整 Phase 2 离线安装成功。

## 12. 范围限制

本次不实现：

- 非 root SSH 用户。
- 自定义 SSH 端口。
- 在线安装模式。
- 用户上传或选择 SSH 私钥。
- 操作系统密钥服务集成。
- 密码轮换和集中凭据管理。
- 节点 sudo 密码。
- 自动删除已保存密码。
